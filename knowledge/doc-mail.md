# 서류 메일 — 문안 커스터마이즈·확인 화면·발송 이력 (2026-08-25 운영자 승인)

서류 묶음을 메일로 보내는 축의 도메인 규칙. 코드 정본은 `lib/docMail.ts`(문안·렌더),
`app/(app)/tenants/docBundle.ts`(초안·미리보기·발송), `lib/mailSend.ts`(발송 유일문).

## 한 프레임, 두 모드

메일의 겉틀(영업장명 헤더 + 테라코타 룰, 첨부 상자, made with stayeum 푸터)은 모든 영업장이
공유하고, **본문 영역만** 영업장이 바꾼다(`Property.docMailTemplate`, null = 내장 기본).

- 기본 모드(text): 제목·본문·맺음말 세 텍스트 칸. 칸별 null = 그 칸만 내장 기본 유지 —
  제목만 바꾼 영업장은 내장 본문 개선을 계속 받는다. 맺음말이 비면 자동 문의 안내
  (전화 있으면 번호, 없으면 회신 안내).
- 직접 HTML(html): 본문 영역 통째 교체. 첨부 상자·푸터는 여전히 프레임 몫 —
  첨부 목록은 발송 시점 사실이라 손으로 쓰게 두면 봉투와 내용물이 어긋난다.

프레임 색은 브랜드 가이드 §26 인쇄 토큰의 hex 하드코딩(메일에는 CSS 변수가 없다),
테이블 + 인라인 CSS + 시스템 한글 폰트 스택, max-width 560px. 웹폰트·외부 이미지 금지.

## 변수 — 문자 템플릿과 같은 단괄호

`{영업장명}` `{이름}` `{서류목록}`. **제목은 `{영업장명}`만** — 제목과 첫 줄은 받는 사람
잠금화면에 뜬다(잠금화면 원칙, [[doc-vocabulary]]의 문안 원칙과 같은 축). `{호실}`은 없다 —
서류 묶음이 여러 계약에 걸칠 수 있어 값이 모호하다.

오타 변수는 **저장 게이트**(`findUnknownVars`)가 막는다. 발송 단계 차단은 없다 — 지원
변수는 발송 시점에 값이 항상 있다. 치환은 이스케이프한 값을 넣는다(값이 태그가 못 된다).

## 새니타이즈 — allowlist, 저장·렌더 이중

`sanitizeDocMailHtml`(sanitize-html). 표·문단·강조 태그와 style 프로퍼티 화이트리스트만
남기고 script·iframe·img·이벤트 핸들러·`url(`·`javascript:` 전부 제거. 저장 때 한 번,
렌더 때 한 번 더(DB 직접 조작·구버전 행 방어). 전부 걷어내져 빈 결과가 되는 HTML 은
저장 자체가 막힌다(소리 없는 강등 금지). **클라이언트는 HTML 을 서버로 보내지 않는다** —
발송 draft 는 텍스트뿐이고, HTML 은 서버가 DB 문안에서만 읽는다(환경설정 미리보기의
폼 값 전송은 예외 — 렌더 결과가 sandbox iframe 으로만 돌아온다).

## 설정과 1회성 수정의 경계

- 환경설정 '서류 메일 문안' 카드(계약서·서류 탭)가 **유일한 저장 자리**.
- 발송 확인 화면(TenantDocMailComposeSheet)의 제목·본문 수정은 **그 한 통에만** 적용되고
  저장되지 않는다. '기본으로 저장' 버튼을 거기 두지 않는다 — 저장 자리가 둘이면 어느 쪽이
  정본인지 흐려진다.
- HTML 모드일 때 확인 화면의 본문 편집은 잠긴다(미리보기만) — 모바일에서 HTML 원문을
  만지다 사고 나기 좋고, 클라이언트가 HTML 을 보내는 금지 축이 열린다.
- 미리보기(환경설정·확인 화면 둘 다)는 발송과 같은 `renderDocMail` 하나가 만든다.

## 발신 도메인 고정·앞부분은 영업장 몫 (2026-08-26 개정)

**도메인은 고정이다.** 메일 서버는 SPF/DKIM/DMARC 로 권한을 증명한 도메인만 발송을
허용하고, stayeum.com 이 그 인증을 지났다. 지메일 주소로 보내는 것은 구글 도메인이라
불가능하고(반송·스팸행), 다른 도메인을 쓰려면 그 도메인마다 인증이 필요하다.

**앞부분(로컬파트)은 영업장이 정한다** — `Property.mailFromLocal`(환경설정 기본정보
'보내는 주소' 칸). 규칙은 `lib/mailFrom` 정본 하나이고 저장·발송·화면 표시가 전부 그
함수를 지난다. 각자 조립하면 화면이 보여준 주소와 실제로 나간 주소가 갈린다.

- 정규화가 `@` 뒤를 잘라내 전체 주소를 붙여넣어도 앞부분만 남는다(손을 받아준다).
- **허용 문자 집합이 곧 보안선이다** — CR/LF·따옴표·꺾쇠가 원천 차단돼 발신 헤더에 다른
  줄을 끼워 넣는 길이 문자 수준에서 막힌다.
- 예약어(RFC 2142 역할 주소 + `stayeum` + `no-reply`)는 저장이 막힌다.
- **`@unique` 다** — 발신 주소는 공개 정체성이라 두 영업장이 같은 주소를 쓰면 받는 사람
  메일함에서 두 사업장이 한 발신자로 묶이고 한쪽 스팸 신고가 다른 쪽을 때린다(publicSlug 와
  같은 판정). nullable 유니크라 미설정 영업장 다수는 충돌하지 않는다.
- **발신 주소 때문에 서류가 안 나가는 경로를 만들지 않는다.** 값이 비었거나 이상하면
  no-reply 로 폴백한다 — 그것이 종전 전 발송과 같은 동작이라 회귀 위험이 0이고, 폴백 사실은
  확인 화면이 같은 함수로 그려 보여준다.

답장 주소는 열거에서만 고른다 — 영업장 주소(`Property.replyToEmail`, 환경설정 '답장 받을
주소' 칸) + 보낸 운영자의 로그인 주소. **답장 주소는 인증이 필요 없어 네이버·지메일 등
어떤 주소든 된다.** 자유 입력은 막는다(오타 한 글자가 답장을 허공에 보낸다). 받는 주소도
저장된 입주자 주소 하나뿐(종전 규칙 그대로).

## 보낸 메일 사본 (2026-08-26)

`Property.mailCopyToSelf` 가 켜져 있으면 **답장 받기로 한 주소로 BCC** 사본이 간다. 같은
메시지의 봉투 수신자라 첨부까지 바이트 동일하다.

- CC 가 아닌 이유: 받는 사람 헤더에 운영자 주소가 노출되고 전체답장 사고를 부른다.
- 별도 발송이 아닌 이유: 본 발송과 사본이 갈릴 수 있다(하나 성공 하나 실패).
- **사본 주소용 칸을 따로 두지 않는다** — 사본이 가야 할 곳과 답장이 와야 할 곳은 같은
  사서함("내가 확인하는 곳")이다. 칸을 셋으로 늘리면 환경설정에서 무엇이 무엇인지 모른다.
- **사본 주소 오타가 서류 발송을 못 막는다.** 한 요청에 to·bcc 가 함께 실려 통째로 거절될
  수 있어, 형식 검사를 통과한 bcc 만 싣고 어긋나면 사본만 조용히 뺀다.
- 받는 사람과 사본 주소가 같으면 안 보낸다(같은 메일이 두 번 갈 이유가 없다).
- **기본은 꺼짐이다** — 신원번호·계약서가 담긴 첨부가 외부 사서함에 쌓이는 일은 영업장의
  명시적 선택이어야 하고, 켜면 메일 서비스 발송 집계가 통당 2로 잡힌다.
- `mail_logs.copyTo` 에 실제로 실은 주소를 남긴다 — "사본을 받았어야 하는데 없다"는 문의에
  토글이 꺼져 있었는지 답할 근거다.

## 발송 이력 — mail_logs

실발송 성공만 한 줄(MailLog): 수신·답장 주소, 제목, 서류 종류, 첨부 파일명 스냅샷, 용량,
resendId(메일 서버 배달 조회 열쇠), 보낸 운영자. **본문은 안 남긴다** — 길고 HTML 이라
저장 가치 대비 개인정보 부피가 크다. 기록 실패는 발송 결과를 뒤집지 않는다.
조회 화면은 [[open-issues]] 백로그.
