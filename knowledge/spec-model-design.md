# 규격·단가 모델 확장 설계안 (2026-07-03, 권고안 승인·시공 완료)

오류신고 3건(89f5cacc·c7cf6180·3707bf65)의 공통 뿌리 — 규격이 "숫자 하나 × 단위 하나"(specValue×specUnit)라는 가정.

## 현 모델과 이미 해결된 부분 (A단계, 2026-07-03 시공)
- Expense 품목: `specValue(숫자) × specUnit(단위) × qtyValue(수량) × qtyUnit` — 예: 2.1 L × 6개.
- **단가 기준 연동(c7cf6180)**: 지출 폼의 규격당/개당 토글 기본값이 품목의 재고 추적 단위(trackUnit)를 따름. 종량제봉투(추적단위=수량)는 개당이 기본. 치수 단위(cm·mm·m·인치) 휴리스틱은 유지.
- **행별 규격 사후 지정(3707bf65)**: 자재 상세 > 구매 내역에서 구매 행별 규격 입력·수정 가능. 자재 카드 묶음 키에 규격이 포함되므로 규격이 달라지면 카드가 자동 분리 → 단가 다른 제품의 임의 배정 해소.

## 남은 문제 (B단계 — 스키마 확장 필요, §4)
1. **다차원 규격(89f5cacc)**: 책상 1200×600×720mm, 블라인드 폭×길이 — 숫자 하나로 표현 불가.
2. **묶음 단가 기준**: "10m가 1롤" 같은 판매 단위 — 현재는 규격당/개당 2택.

## 설계 옵션
### 옵션 1 — 서술형 규격 필드 추가 (권고, 최소 침습)
- `Expense.specText String?` (예: "1200x600x720mm", "40mm용"): **표시·카드 구분에만 참여, 계산 비관여.**
- 자재 묶음 키에 specText 포함 → 사이즈 다른 제품 분리. 소모품 수학(specValue 환산)은 기존 그대로 → §4 리스크 최소.
- 마이그레이션: 컬럼 추가만(NULL 허용). 폼: 규격 입력에 "직접 서술" 토글.

### 옵션 2 — 다차원 구조화 (보류 권고)
- `spec Json?` = [{dim:'W',v:1200,u:'mm'},...]. 계산·비교·검색까지 구조화되지만 입력 UX 복잡, 소모품 환산 수학 전면 수정 — 상용화 전 단계에서 과설계 위험.

### 옵션 3 — 단가 기준 저장
- `Expense.unitBasis String?` ('spec'|'qty'|'bundle') + bundle 크기. 옵션 1과 병행 가능. 최소형: 현행 토글 값 저장만이라도(재열람 시 기준 보존).

## 권고 → 시공 완료 (2026-07-03, 운영자 승인)
**옵션 1 + 옵션 3 최소형** 시공됨: prisma/migrate_expense_spec_text.sql 적용(specText·unitBasis),
지출 폼 '서술형 규격' 토글(개당 단가 자동), 자재 묶음 키·표기·검색·행별 편집 반영. 계산 로직 무변경 확인(빌드·tsc).
