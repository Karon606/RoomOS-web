# 청소 도메인 — 결함 대장과 규칙

2026-08-11 청소·지출 정합 조사에서 나온 결함 5건(D1~D5)의 정본 기록. 당시 운영자가 청소 탭 신설과 함께 홀드했고, 2026-08-12 구조 개편(호실 관리 '호실/청소' 뷰 탭) 승인으로 봉합이 재개됐다. D4 만 먼저 구현돼 있다.

## 결함 대장

- **D1 — 삭제가 지출이 남는 사실을 안 알린다.** 청소 완료 내역을 삭제해도 연결된 지출(Expense)은 남는데 확인창이 침묵한다. 적용취소는 알리는데 삭제만 조용하다. 좌표 RoomCleaningPanel 삭제 확인창 — 그 행에 지출이 걸려 있으면 문구를 갈라 알린다.
- **D2 — 삭제 적용취소 진입점 부재.** `restoreCleaning`(cleaningActions)이 정의만 있고 호출처 0. 삭제가 소프트삭제인데 되살릴 UI 가 없다 — [[rollback-always-required]] 위반. 최소안은 삭제 토스트에 '적용취소' 액션(지출 삭제의 토스트 undo 문법, FinanceClient 선례).
- **D3 — 재완료 시 비용 0 이면 지출 연결이 조용히 끊긴다.** 서버는 그대로 두되(지우는 판단은 운영자 몫), 클라이언트에서 원래 금액이 걸려 있는데 0 으로 저장하려 하면 확인창 한 번.
- **D4 — 고아 청소 지출 감지망.** `scripts/check-cleaning-expense-orphan.mjs` 로 **구현 완료**(2026-08-11, verify:db). 두 방향 — 살아 있는 청소가 삭제·부재 지출을 가리킴, 방 걸린 청소용역비 지출이 어느 청소에도 안 걸림.
- **D5 — `fromCleaningFund=true` 인데 지출이 없어 부담액 0 인 유령 표식.** 표식 렌더 조건에 금액 유무를 함께 본다.

2026-08-12 패널 조사가 추가로 적은 것 — 영업장 전체 청소 목록·기간 조회 부재(뷰 탭 신설로 해소 예정), 청소비 잔고 영업장 합계 화면 부재, Expense 에 청소 역참조 없음(단방향 uuid).

## 분류 규칙 (운영자 확정 2026-08-11)

보증금 안의 청소비 몫(계약의 cleaningFee)을 퇴실 때 쓰는 것은 **'청소비' 수익**이다. '보증금 몰취'는 잔여 몫에서 파손 등을 차감할 때만 쓴다. 정본은 `lib/depositComposition.splitWithheldDeposit` — 사유 텍스트가 아니라 계약 구조로 가른다. 관련 [[domain-billing]].

## 수행자 규칙 (운영자 확정 2026-08-11)

무상 청소 = 업체(고시클린) 서비스, 지출 0 이 정상. 유상인데 수행자가 개인 이름(이춘옥)인 것은 청소업체 분에게 개인적으로 지급했기 때문 — 분류는 업체(VENDOR) 유지, 이름만 개인.
