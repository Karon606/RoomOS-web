# 서류 변수 허브 — 사전은 설명서, 값의 정본은 각 DB 필드

2026-09-01 운영자 승인(패널 설계). 계약서·동의서·문자·메일의 치환 변수와 변수 없이 종이에
직접 박히는 영업장 값을 환경설정 계약서·서류 탭의 "서류 변수 한눈에" 카드와 허브 모달에서
조망·수정한다.

## 정본 규칙

- **허브는 같은 DB 필드를 편집하는 또 하나의 문이다.** 저장은 기존 정본
  (updatePropertySettings 부분 저장·saveBusinessInfo)을 그대로 재사용 - 별도 저장소를 만들면
  그 순간 사본이라 언젠가 갈린다. 열 때마다 서버에서 새로 읽는다(낡은 값 저장 방지, 적대 검토 조건).
- 변수 사전 정본은 `lib/docVariables.ts` (DOC_VARIABLES 40건·DOC_TEMPLATES 10건). 사전은
  설명서일 뿐 값 저장소가 아니다. 감지망 `check-doc-variable-registry.ts`(verify:fast)가
  사전과 실제 치환 코드(인쇄 vars·dcVars 블록, replaceAll·치환 맵 키)·점프 앵커를 양방향 대조한다.
- 치환 문법이 네 벌이다. 계약서 본문 {{영문}}, 동의서 {{한글}}, 문자 { }, 메일 { }.
- **{영업장명}은 두 원천이다.** 문자·메일 = Property.name(간판 이름), 동의서 = businessInfo.name
  (등기 상호). 서로 다른 사실이라 합치지 않고 라벨로 가른다(운영자 승인). 주소도 두 갈래
  (건물 소재지 Property.address / 등록증 표기 businessInfo.address).
- 계약별 값(성명·호실·일정 등)은 수정 대상이 아니라 **미리보기 대상** - 계약을 골라 실제
  치환값을 본다. 외국인등록번호는 미리보기에서 항상 마스킹(종이에는 전체가 찍힌다).
- 긴 문안(계약서 본문·특약·문자 템플릿·메일 문안)은 허브에서 열지 않는다 - 원래 편집기로
  점프만 한다(편집기 복제 = 두 벌).
- 파생 변수({미납금액}·{{단기요금표}} 등)는 원천이 없다 - 보낼·뽑을 때 계산.
- 동결: 허브에서 고친 값은 다음 발급부터. 서명된 계약서(signedContractSnapshot)와 발급된
  서류(issuedSnapshot·Drive PDF)는 안 바뀐다 - 허브 상단 고정 안내로 고지.
