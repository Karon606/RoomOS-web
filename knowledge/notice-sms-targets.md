# 단체 공지 대상 그룹 — 입주자 | 문의·예약, 우선권은 문의일 범위 웨이브 (2026-10-06, 운영자 승인)

운영자 원문: "단체문자 보내는 기능에서 문의예약했던 사람들도 조건에 들어가면 좋겠어. 목적은 일괄 발송해서
선착순 예약(예약금 입금한 예약확정)을 받을 수 있도록. 이들에 대한 조건은 문의한 날짜의 범위도 들어가면 좋을 듯.
먼저 문의한 사람에게 우선권을 줘야 하니까"

## 그룹 둘 (정본 `lib/noticeTargets.ts` `classifyNoticeTarget`)

| 그룹 | 정의 | 비고 |
|---|---|---|
| 입주자(기본) | `CURRENT_OCCUPANCY_STATUSES`(거주중·퇴실 예정) + 방 있음 | 종전 단체 공지 모집단 그대로 |
| 문의·예약 | `WISH_LEAD_STATUSES`(문의·투어·입실 예약) + **예약 확정 아님**, 방 조건 없음 | 입주자 관리 '문의·예약' 그룹과 같은 집합 |

- **확정 제외는 리드 갈래에만 건다.** 거주중 계약도 `reservationConfirmedAt` 을 그대로 들고 있다(예약 확정 뒤
  입실한 사람, 2026-10-06 실측 제기역점 ACTIVE 3건). where 전체에 `reservationConfirmedAt: null` 을 걸면 그
  입주자가 공지에서 빠진다. 서버 where 는 `OR: [거주 갈래, 리드 갈래]` 이고 확정 제외는 리드 갈래 객체 안에만 있다.
- 예약 확정자는 이미 예약금을 낸 사람이라 선착순 안내 대상이 아니다. 취소자(CANCELLED)는 두 상수 어디에도
  없어 저절로 빠진다. **취소자 재안내는 2차 후보**(토글로 넣을지 운영자 판단 대기, 제기역점 취소 38건).
- 상태 문자열은 사본 금지. `noticeSms.ts` 안에 계약 상태 리터럴이 하나라도 있으면 그물이 붉다.
- 문의 단계(문의·투어·입실 예약) 판정 `inquiryStageOf` 와 라벨 `LEAD_STAGE_LABEL` 은 `lib/wishMatch.ts` 한 곳이다
  (입주자 관리 화면 안 로컬 함수였던 것을 올렸다). 입주자 관리 2차 세그먼트와 단체 공지 '단계' 칩이 같은 값을 쓴다.

## 우선권은 순서가 아니라 웨이브로 준다

단체 공지는 배치 전체가 한 본문을 공유한다(치환 없음, §29). 그래서 "먼저 문의한 사람에게 우선권"은 한 문자 안의
순서로 줄 수 없고, **문의일 범위로 나눠 먼저 보내는 것**으로 준다. 9월 문의자에게 먼저, 며칠 뒤 10월 문의자에게.
확정은 예약금 입금 순(운영자가 확정 처리)이다.

- 문의·예약 목록은 **문의일 오름차순 고정**(문의 일시, 없으면 등록 일시 — `lib/wishMatch` orderAt 과 같은 정의).
  문자 묶음(20명)도 보이는 목록 순서로 잘려 첫 묶음이 먼저 문의한 사람들이다.
- **순번은 리드 전체 기준**(단계·문의일·다른 조건으로 거르기 전). 9월만 고른 화면의 '2번'과 전체 화면의 '2번'이
  같은 사람이어야 운영자가 말하는 '몇 번째 문의'가 갈리지 않는다. 동률은 등록 순, 그다음 id.
- 문의일 범위는 KST 일 경계 양끝 포함(시작일 00:00 ~ 끝일 23:59). 편집기는 지출 엑셀 내려받기 기간 선택 정본
  (1·3·6개월/전체/직접 지정). 프리셋도 적용 순간의 날짜로 박는다(드래프트를 이튿날 열어도 칩과 거르는 범위가 같다).
- 행 보조줄 `문의 9/9 · 투어 10/1 · 공지 9/20`('명사 날짜' 한 어순). '공지'는 그 사람의 마지막 단체 공지 발송 시도
  (`SmsLog kind 'notice'` tenantId 별 최근 createdAt) — 이미 웨이브를 받은 사람을 가려 보게 한다.
- 날짜 표기는 **해가 다를 때만 연도**(`fmtMDYearIfOther`, 정본 `leadSubLine`·`inquiryRangeLabel`). 지난해 문의를 '12/1'로만
  쓰면 최근 문의처럼 읽힌다. '안내함'은 쓰지 않는다 — 기록은 발송 **시도**라 단정 어휘가 거짓이 된다(웹디자이너 패스 2026-10-06).
- 문의일 직접 지정의 날짜 칸 둘은 좁은 폭에서 1열(`grid-cols-1 min-[400px]:grid-cols-2`, 형제 폼과 같은 문턱). 카드 안이라 2열이면
  '2026년 10월 16일'이 360px 에서 잘린다. 순번 칸은 목록과 제외 패널이 같은 한 벌(w-6 우정렬 tnum).
- 조건을 바꾸면(그룹·문의일·값 축) 묶음의 '기록됨' 표시를 비운다. 표시가 묶음 순번(0,1,…)에 붙어 있어서
  범위를 바꾼 다음 웨이브의 첫 묶음이 '기록됨'으로 보이고 기록이 건너뛰어지던 길이다.

## 화면 (components/NoticeSmsModal.tsx)

- 맨 위 SegmentedControl sm `입주자 N | 문의·예약 N`, 기본 입주자. 옛 드래프트(그룹 없음)·모르는 값·'새로 작성'은 입주자.
- 문의·예약에서는 방 축(층·창·방향·등급·타입·거주기간·결제수단)이 **숨는다**(§22, 비활성 아님). '단계' 칩과 '문의일'
  칩이 선다. 축 선택지는 고른 그룹 사람만으로 센다.
- 호실 자리에 순번(우정렬 w-6 tnum). '보낼 대상 · N명' 행 우측에 전체 선택/해제(§23, 보이는 목록 중 본인 번호 행만,
  비상 대체 행은 직접 체크).
- 이력 머리 `[단체 공지 · 문의·예약 · 문의일 9/1~9/30] 본문`, 입주자는 `[단체 공지 · 입주자 · 4층]`. SmsLog 에
  `leaseTermId` 도 남긴다(한 사람이 문의를 여러 건 가질 수 있다).

## 예시 템플릿 '선착순 입실 안내' (lib/noticeTemplates.ts)

공지 템플릿은 영업장별 DB 행뿐이고 코드 기본값이 없었다. DB 에 심으면 영업장마다 쓰기가 필요하고 저장 목록과
섞이므로 **코드 본보기**로 두고 발송 화면 드롭다운에서만 합친다(묶음 제목 '저장한 템플릿' / '예시 문구' — '기본'이라 부르지 않는다, 설정에서 관리하는 템플릿과 다른 것이다).
같은 이름·본문을 저장했으면 예시는 빠진다. 설정 화면 목록에는 안 보인다. 본문에 영업장명·{변수} 없음,
달·날짜·실수·계좌는 운영자가 고쳐 쓰는 본보기 값이다.
