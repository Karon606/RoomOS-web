# 참고용 번역본 검수 종이 — 저장되지 않는 PDF (2026-09-17)

운영자 오더에서 나온 정본. 코드 정본은 `lib/contractTranslationPrintHtml.ts`(조판·글꼴)와
`app/api/contract-translation/pdf/route.ts`(관문). 번역본 자체의 판정 정본은
[[domain-contracts]] 옆의 `lib/contractTranslation.ts` 이고 여기는 **그 결과를 종이로 뽑는 길**이다.

> "난 한자를 못읽기 때문에 알수가 없어... 모든 번역본에 대해서는 pdf로 다운로드 받을 수 있게 해줘."
> "띄우는 것은 좋은데 다운로드 받을 수 있는 버튼을 알려줘야지 창을 끄니까 다시 방법이 없어"

## 무엇을 위한 종이인가

**검수용이다.** 운영자가 환경설정에서 편집 중인 번역을 종이로 받아, 그 언어를 읽을 줄 아는
사람에게 보내 "이 번역이 맞느냐"를 묻는다. 입주자용이 아니고 계약서도 아니며 앱에 보관되지도
않는다. 화면 미리보기는 창을 끄면 사라지고, 사라지면 물어볼 방법이 없다 — 그것이 이 기능이
생긴 이유다.

**저장 전 입력칸(draft)이 원천이다.** 저장본을 읽으면 "저장하기 전에 맞는지 확인"이라는 쓰임이
앞뒤로 뒤집힌다. 그래서 클라이언트가 `{ lang, dict }` 둘을 보내고 서버가 나머지를 DB 에서 읽어
**설정 화면 미리보기(`SettingsForm` 의 `preview` useMemo)와 한 글자도 다르지 않은 인자**로
`resolveContractTranslation` 을 부른다. 인자가 하나라도 달라지면 창과 종이가 갈린다.

## 언어별 글꼴 — 실측이 지도의 근거다

Pretendard 를 fontTools 로 열어 센 결과(2026-09-17).

| 구간 | Pretendard 보유 |
|---|---|
| 키릴 (U+0400~04FF) | 254 / 256 |
| 라틴 확장 추가 (U+1E00~1EFF, 베트남어 성조) | 256 / 256 **전량** |
| 한글 음절 (U+AC00~D7A3) | 11,172 **전량** |
| 가나 | 184자 |
| **CJK 한자 (U+4E00~9FFF)** | **0자** |
| **벵골 (U+0980~09FF)** | **0자** |

그래서 지도는 이렇다(`TRANSLATION_SCRIPT_FONT`).

| 언어 | 코드 | 실리는 글꼴 |
|---|---|---|
| 영어 | en | Pretendard 만 |
| 베트남어 | vi | Pretendard 만 |
| 러시아어 | ru | Pretendard 만 |
| 일본어 | ja | NotoSansJP-Regular + Pretendard |
| 중국어 간체 | zh | NotoSansSC-Regular + Pretendard |
| 중국어 번체 | zht | NotoSansTC-Regular + Pretendard |
| 벵골어 | bn | NotoSansBengali-Regular + Pretendard |

- **Pretendard 는 어느 언어에서도 빠지지 않는다.** 고지 박스의 한국어 줄과 번역이 없어 한국어로
  남은 줄이 항상 함께 서기 때문이다. Noto 넷에는 한글이 0자다.
- `font-family` 순서는 `'그 언어 글꼴', 'Pretendard', sans-serif` 다. 뒤집으면 일본어 한 낱말에서
  가나는 Pretendard 가, 한자는 Noto 가 그려 한 낱말이 두 서체로 갈린다.
- `null` 은 결손이 아니라 **"Pretendard 로 충분하다"는 판정**이다. 지도는 `Record<TranslationLang,
  string | null>` **전량 선언**이라, 언어가 늘었는데 판정을 안 적으면 tsc 가 막는다
  (`TRANSLATION_NOTICE`·`TRANSLATION_LANG_ENDONYM` 과 같은 수법).

## 왜 `public/fonts-i18n` 인가 — `public/fonts` 에 섞지 않는다

`next.config.ts` 가 `/api/contract/generate` 와 `/api/rent-receipt/generate` 에
`'./public/fonts/**'` 글롭을 걸고 있다. Noto 넷(합계 약 9.3MB)을 거기 넣으면 **그 두 라우트가 쓰지도
않는 9MB 를 번들에 진다.** 입실료 납부 확인서는 상시 경로라 콜드 스타트가 그대로 느려진다.

반대로 **기존 두 줄의 글롭을 좁히지도 않는다.** 좁히면 `getPretendardBase64()` 가 조용히 CDN
폴백으로 내려앉아 신고 0aed3bdd(간헐 발급 실패)가 되살아난다. 새 라우트만 세 항목을 진다
(`chromium` · `./public/fonts/**` · `./public/fonts-i18n/**`).

**글꼴 파일의 출처.** 넷 다 Google Fonts(`fonts.gstatic.com`)에서 받은 원본이고 한 바이트도 고치지
않았다. NotoSansJP/SC/TC 는 Version 2.004-H2, NotoSansBengali 는 Version 3.011. 라이선스 사본은
`public/fonts-i18n/OFL.txt`(SIL OFL 1.1 + 두 저작권 고지)이고, 그것이 재배포 준수의 전부다.

> 처음 치워 둔 후보 넷은 **버렸다.** fontTools 로 열어 보니 이름은 `-Regular` 인데 실제 내부
> 이름이 `Noto Sans JP Thin` 이었고(글립 수도 7,466 대 16,662 로 부분집합), 8.7pt 본문에서 Thin 은
> 종이에서 거의 안 보인다. 출처가 불명일 때는 다시 받는다.

## 왜 글꼴 실패에 부분 성공이 없는가

`getPretendardBase64()`(계약서)는 글꼴을 못 구해도 발급을 막지 않는다. 한글이 깨져도 운영자가
눈으로 알아채기 때문이다. **이 종이는 규칙이 반대다.**

운영자는 한자·벵골 글자를 스스로 읽지 못한다. 그래서 **두부(□)와 정상 글자를 구별하지 못한다.**
네모로 찍힌 종이를 검수자에게 보내면 검수자는 "번역이 틀렸다"고 답하고, 그 답은 거짓이다.
그러면 운영자는 멀쩡한 번역을 고치게 된다.

그래서 `translationScriptFontBase64()`·`translationPretendardBase64()` 에는 **CDN 폴백이 없고,
못 읽으면 예외를 던진다.** 라우트가 그것을 잡아 503 `FONT_UNAVAILABLE` 로 답한다.

> "이 언어의 글꼴을 서버에서 찾지 못해 종이를 만들 수 없습니다. 글자가 네모로 나가는 종이를
> 내보내는 것보다 여기서 멈추는 편이 낫습니다."

## 저장하지 않는 종이 — 그래서 적용취소가 없다

이 라우트에는 `prisma` 의 create·update·delete·upsert 도 `uploadToDrive` 도 없다. 읽기 하나뿐이다.
**되돌릴 상태가 없다는 것이 적용취소가 필요 없는 근거의 전부다**(`rollback-always-required` 원칙의
경계). 저장을 한 줄 들이는 순간 그 근거가 사라지는데 그 변화는 화면에서 아무 소리도 안 내므로,
`scripts/check-translation-print.mjs` 축 4 가 그것을 지킨다.

**번역문을 클라이언트에서 받는 것이 계약서 라우트 규칙을 어기지 않는 이유.**
`app/api/contract/generate/route.ts:109~111` 의 "번역 내용은 받지 않는다"가 막는 것은 **법적 효력이
있는 종이에 임의 문안을 박는 것**이다. 여기에는 계약도 입주자도 금액도 서명도 없고 DB·Drive 에
안 남는다. 한국어 원문·사전의 열쇠·조항 순서는 여전히 서버가 정하며, 이 관문을 부를 수 있는
사람은 이미 본문 자체를 고칠 수 있는 OWNER·MANAGER 다.

## 종이에 서는 것과 안 서는 것

**선다.** 머리 한 줄(`참고용 · 계약서 아님 / Reference only · Not a contract` + 그 언어의 자기 이름
+ 만든 날짜 KST) · 고지 박스(`translationNoticeBi` 정본, 한국어 줄 + 그 언어 줄) · 검수 안내 한
줄(한/영, `{{ }}` 가 그대로 보이는 것이 고장이 아니라는 말) · 진행 한 줄 · 본문(제목·절·항목·가변
절·서약문) · 번역이 없어 한국어가 남은 줄의 회색 `원문` 표식 · **모든 장** 꼬리말
(`참고용 번역본 · 계약서 아님 / Reference translation, not a contract` + 페이지 번호).

**안 선다.** 계약번호 · 로고 · 도장 · 서명란 · 워드마크 · 정보표 · 입주자 이름 · 생년월일 ·
등록번호 · 금액표 · 영업장명. **계약번호는 절대 찍지 않는다** — 소비되지 않은 번호가 종이로 나간
E페이즈 사고가 있었다. 영업장명·워드마크를 안 넣는 것은 **카드에 없는 것을 종이에 넣지 않는다**는
운영자 확정이다.

**조판은 계약서와 일부러 다르다**(운영자 확정, `checklist.md` 12번 — "계약서와 동일한 포맷으로
하면 오히려 헷갈릴 수 있으므로"). 계약서는 2단에 헤더 밴드가 있고, 이 종이는 1단이고 그것이 없다.
화면 카드(`ContractTranslationView`)가 앱 문법으로 같은 결정을 이미 한 자리다.

**조항 안의 `{{변수}}` 는 치환하지 않는다.** 계약이 없는 자리라 값을 지어내면 그것은 검수가
아니라 거짓이다. 해석이 제 값을 들고 온 변수(환불 규정·청소비 문장)만 채워지는데, 그 규칙은
화면 미리보기가 `ContractTranslationBody` 에 `vars` 를 안 넘기는 그 호출과 문자 단위로 같다.

## 감지망

| 축 | 어디 | 무엇을 지키나 |
|---|---|---|
| 0 | tsc | 글꼴 지도 `Record` 전량 선언 — 언어가 늘면 컴파일이 막힌다 |
| 1 | `check-print-selfcontained.ts` | 종이에 외부 참조 0건 · 임베드 글꼴이 **두 벌**(그 언어 + Pretendard), 폴백 언어는 한 벌 |
| 2 | 〃 | `FONT_FILE_RE` 에 Noto 넷 포함 — 새 라우트가 폰트 소비자로 잡혀 번들 명단과 대조된다 |
| 3 | 〃 | 지도가 지목한 파일이 `public/fonts-i18n/` 에 실재하고 20KB 이상(LFS 포인터·잘린 파일) |
| 4 | `check-translation-print.mjs` | 라우트에 prisma 쓰기·`uploadToDrive` 가 없다 |
| 5 | 〃 | 종이 머리와 **꼬리말 템플릿 양쪽**에 참고용 표식이 있다 |
| 6 | 〃 | 해석 결과의 제목·절 제목·항목·가변 절·서약문이 **순서대로 전부** 종이에 선다 |

`package.json` 의 `verify:fast` 에 등록돼 있다 — 훅은 이름을 나열하지 않으므로 등록이 곧 실행이다.

## 실측 (2026-09-17, 제기역점 실제 사전 48줄 · 로컬 Chrome)

| 언어 | HTML | setContent | pdf | 장수 | 두부 |
|---|---|---|---|---|---|
| en · vi · ru | 2.6MB | 200~240ms | 약 350ms | 3 | 0 |
| bn | 2.7MB | 238ms | 337ms | 3 | 0 |
| ja | 5.4MB | 442ms | 353ms | 3 | 0 |
| zht | 6.3MB | 513ms | 356ms | 3 | 0 |
| zh | 7.9MB | 673ms | 363ms | 3 | 0 |

`setContent` 상한은 **이 라우트만 25초**다(계약서는 15초). 재료가 다르기 때문이다 — 중국어 간체
종이는 base64 로 약 8.4MB 를 싣고 계약서는 2.7MB 한 벌뿐이다. 25초 x 2회(1회 재시도)가
maxDuration 60초 예산 안에 든다. **계약서 라우트의 상한은 건드리지 않았다.**

두부 검사는 실제 저장 사전으로 돌린 전수 대조다 — 종이에 실제로 오른 글자 종수(ja 564 · zh 577 ·
zht 569 · bn 170 · en 143 · vi 195 · ru 172) 전부가 (그 언어 글꼴 ∪ Pretendard)에 들어 있다.

## 화면에서 부르는 자리 둘

1. 카드 안 도구 줄 — `한국어 전문 복사` · `번역 붙여넣기` · `미리보기` 옆 **넷째**. 앞 셋과 성격이
   같다(저장하지 않는 도구, 지금 편집 중인 언어를 따라간다).
2. 미리보기 모달 `footer` — 창을 끄면 화면이 사라지므로 나가는 길 옆에 종이로 받는 길을 둔다.

둘 다 정본 `components/ui/SendDocButton` 이다. 사진/PDF 2단 선택 · 아이폰 공유 시트 경로와 안내 ·
제스처 만료 재시도 · 데스크톱 폴백 · 0바이트 가드(신고 5c99b5c8)가 이미 그 안에 있다. 직접
`a.download` 를 쓰면 아이폰에서 또 "방법이 없어"가 난다. **`label` prop 은 넘기지 않는다**
([[doc-vocabulary]]) — 기본값 '내보내기'가 정본이고 UI 에 '다운로드'라는 낱말을 쓰지 않는다.
**인쇄 버튼을 따로 내지 않는다**(`lib/useDocPrint.ts` 가 두 번째 인쇄 경로를 금지한다).

파일 이름은 `참고용번역본_{그 언어의 자기 이름}_{YYYYMMDD}` 다(확장자는 SendDocButton 이 형식에
따라 붙인다). 정규화는 `/[^\p{L}\p{N}_-]+/gu` 를 `_` 로 — 유니코드 letter 를 살려 한글·한자·벵골
글자가 남는다. 입주자 이름도 영업장명도 없다, 종이에 그런 값이 한 글자도 안 실리기 때문이다.

## 계약서 체크리스트(A~F) 판정

[[domain-contracts]] 의 A~F 를 지난 결과다.

- **A~D 해당 없음.** 서명도 링크도 알림도 이름 인쇄도 없다.
- **E 는 의도적으로 안 한다.** 발급본이 아니다. `printedFacts` 축을 늘리면 조항을 한 글자도 안
  고친 **발급본 전건이 허위 드리프트로 뜬다**(추가 서류·특약 축의 '없으면 축도 없다'와 같은 사정).
- **F 는 했다.** 새 그물을 `verify:fast` 에 등록했고, 역주입 10건이 전부 발화했다.
  **import 만 남기고 호출을 지우는 수법**도 포함한다(`appendSubLeaseAddendum` 을 import 한 채 안
  부르면 가변 절이 통째로 빠지는데 축 6 이 잡는다). 원복은 백업 파일 `cp` + `cmp` 로만 했다.
