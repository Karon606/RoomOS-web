# 영업장 관리 메모 (PropertyNote)

신고 d1e5fecc, 2026-11-02 운영자 승인. 계절마다 바꾸는 설정처럼 때가 지나면 잊는 내용을 영업장 단위로 적어 두는 곳이다.

## 무엇이 참인가

- 표는 `property_notes`(Prisma `PropertyNote`). 제목·본문·분류 한 개(`tag`)·차례(`sortOrder`)·`deletedAt`. 운영 SQL `prisma/migrate_property_notes.sql`(멱등).
- **Room.memo 와 다른 축이다.** 그것은 방 하나의 '메모'이고 이것은 영업장 전체의 '관리 메모'다. 화면 이름도 겹치지 않는다.
- 진입은 호실 관리 헤더(호실 뷰) `관리 메모` Btn secondary md 하나. 읽기라 STAFF 에게도 서고, 쓰기 버튼(장마다 [수정]·맨 아래 `+ 메모 추가`)만 편집 권한일 때 선다. 헤더 CTA 가 셋이 되는 것은 §23 예외(운영자 승인)이고, `관리 메모`를 맨 뒤에 두어 320px 에서 접혀도 `+ 호실 등록`이 첫 줄에 남는다.
- 목록 Modal(z 200) 안에 장마다 제목 13px/700, 본문은 줄바꿈 그대로(자르지 않는다), 분류는 §11 메타 칩. 추가·수정 Modal 은 목록의 형제(z 260). 수정은 §27.1 RecordEditShell, 삭제는 발끝 `관리` 메뉴.
- 빈 상태 `관리 메모가 없습니다` / `계절마다 바꾸는 설정처럼 때가 지나면 잊는 내용을 적어 두세요.`
- 입력 정본 `lib/propertyNote` normalizeNoteInput. 제목 필수 60자, 본문 선택 4000자, 분류 선택 20자. 화면의 저장 막힘 이유와 서버 거부가 같은 함수·같은 문장.
- 서버 `app/(app)/room-manage/noteActions.ts`. 목록은 창을 열 때 읽는다(페이지 로드에 얹지 않는다). 그래서 표가 없는 DB 에 배포돼도 이 창만 실패하고 다른 화면은 안 깨진다.

## 적용취소(§16)

모두 서버 조건부 쓰기다. 토큰은 서명하지 않는다(편집 권한이면 어차피 아무 값이나 적을 수 있는 메모라 위조로 넘을 경계가 없다). 대신 버전이 맞을 때만 쓴다.

- 추가: 만든 직후 그대로(updatedAt)일 때만 삭제 도장을 찍는다(소프트삭제, 독립 검수 R3). 그사이 고쳤으면 거부.
- 수정: 저장 직후 그대로일 때만 저장 직전 모습 전체로. 수정 자체도 연 순간의 updatedAt 그대로일 때만 쓴다.
- 삭제: deletedAt 도장. 그 도장 그대로일 때만 되살린다.
- 진입점은 토스트 [적용취소] 하나다. 토스트가 사라진 뒤 삭제한 메모를 되살리는 화면은 없다(점검 기록 삭제와 같은 수준, 남은 과제).

## 백업

설정의 전체 JSON 백업(exportAllData)에 `propertyNotes` 가 들어간다(삭제분 제외, 같은 날 방 작업·방 점검도 함께 넣었다). 엑셀 내보내기에는 없다.
