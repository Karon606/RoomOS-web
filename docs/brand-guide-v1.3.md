## §09 확인 다이얼로그 (Confirm Dialog)

네이티브 `confirm()`/`alert()` **전면 금지** (71곳 전수 교체 대상). 공용 `<ConfirmDialog>` 하나로 대체한다.

### 9.1 공통 스펙
| 항목 | 값 |
|---|---|
| 너비 | `--confirm-w` 360px (영향 고지형 420px) / max `calc(100vw - 32px)` |
| radius | r-2xl 18px |
| 배경 | `--cream`, backdrop `rgba(0,0,0,.7)` |
| z | `--z-confirm` 340 |
| 패딩 | 24px (헤더·본문·푸터 일체형, 내부 구분선 없음) |
| 제목 | 16px / 700 / `--ink` |
| 본문 | 13.5px / 400 / `--ink-s` / lh 1.65 |
| 버튼 | btn-md 40px, **취소 좌 · 확인 우** (v1.2 modal-foot과 동일) |
| 등장 | opacity+scale(.96→1) 200ms `cubic-bezier(.4,0,.2,1)` |
| 포커스 | 열릴 때 **취소 버튼**에 초기 포커스 (오조작 방지) |

### 9.2 3단계 위험도

| | ① 일반 확인 | ② 주의 | ③ 파괴적 (영구 삭제) |
|---|---|---|---|
| 용도 | 기록 저장·상태 전환 | 되돌리기 가능한 변경 | 복구 불가 삭제 |
| 아이콘 | 없음 | 경고 삼각형 20px `#8B5E0A` | 경고 원형 20px `--tc` |
| 확인 버튼 | btn-primary | btn-primary | **solid `--tc`** + 동사 라벨 ("영구 삭제") |
| 취소 버튼 | btn-ghost | btn-secondary | btn-secondary |
| Esc 닫기 | 허용 | 허용 | 허용 (= 취소) |
| 배경클릭 닫기 | 허용 | **무시** | **무시** |
| 추가 요소 | — | — | 영향 목록 박스 (9.3) |

확인 버튼 라벨은 항상 **동사** ("저장", "전환", "영구 삭제"). "확인"·"예" 금지.
③의 solid `--tc` 근거: 다이얼로그 안에서 CTA는 하나뿐이므로 OVERDUE 강조색과 충돌 없음. v1.2 btn-danger(soft)는 ③에 쓰기엔 무게가 부족하다.

### 9.3 파괴적 단계 — 영향 고지형 레이아웃 (confirm 2연타 대체)

```
┌──────────────────────────────────┐
│ ⚠ 입주자 기록을 영구 삭제할까요?     ← 제목 16/700, 아이콘 좌측 8px
│                                  │
│ ┌────────────────────────────┐   │
│ │ 함께 삭제되는 항목            │   ← 영향 목록 박스
│ │ · 과거 계약 3건              │     bg: rgba(160,60,46,.06)
│ │ · 수납 기록 24건             │     border: 1px rgba(160,60,46,.2)
│ │ · 첨부 서류 2건              │     radius: r-md 8px, 패딩 12px 14px
│ └────────────────────────────┘   │     항목 12.5px --ink-s, 건수 tnum 600
│                                  │
│ 이 동작은 되돌릴 수 없습니다.        ← 경고문 12px / 600 / --tc-d
│                                  │
│            [취소]  [영구 삭제]     │
└──────────────────────────────────┘
```

- 영향 건수는 **반드시 실데이터** (서버 카운트). 건수를 모르면 이 다이얼로그를 띄울 수 없다.
- 2차 동의가 더 필요한 초고위험(예: 건물 전체 삭제)만 입력 확인("삭제를 입력하세요") 추가 — 그 외 confirm 2연타·체크박스 동의 금지.

### 9.4 액션 시트형 (선택지 3개 이상)

- 세로 버튼 리스트. 각 행 높이 48px, 텍스트 14px/500 `--ink`, 좌측 정렬 + 아이콘 16px.
- 행 사이 구분선 `--border`. hover bg `--cream-2`. 파괴적 선택지는 텍스트 `--tc`.
- 취소는 리스트와 **분리된** 하단 단독 버튼 (btn-ghost, full width, 상단 여백 8px).
- 모바일(<768px): 바텀시트로 전환 — 하단 고정, 상단 radius 18px, safe-area 패딩.

**Do**: 삭제 확인 제목에 대상 이름 명시 ("401호 김건우 기록을…").
**Don't**: 다이얼로그 안에 또 다이얼로그 (액션시트→확인 1회는 허용, 그 이상 금지).

## §10 적용취소 (Undo)

제품 원칙: **"적용하는 모든 기능엔 적용취소가 항상 있어야 한다."**

### 10.1 용어 통일
- 표준 라벨: **"적용취소"** 단일. '해제', '병합 해제', '다시 포함', '되돌리기' 전부 교체.
  근거: 제품 원칙 문구와 동일 단어를 써서 라벨만 봐도 원칙이 상기되게 한다.
- 대상이 모호할 땐 명사 보강: "병합 적용취소", "면제 적용취소".
- 아이콘: rotate-ccw (반시계 화살표) 14px, 라벨과 6px 간격. 아이콘 단독 사용 금지.

### 10.2 진입점 표준 (우선순위)
1. **토스트 액션** — 적용 직후 6초간: `[적용취소]` 버튼 포함 토스트 (§11.4).
2. **원위치 버튼** — 적용 결과가 보이는 바로 그 위치(위젯·행·카드)에 btn-subtle sm.
3. 상세 화면 액션 메뉴 — 1·2를 놓친 뒤에도 접근 가능해야 함.

토스트는 보조 수단이다 — 토스트가 사라져도 2·3으로 항상 취소 가능해야 원칙 충족.

### 10.3 되돌릴 수 없는 동작의 구분
- 버튼·메뉴 라벨 옆 캡션: `(되돌릴 수 없음)` 10.5px `--tc-d`.
- 실행 전 반드시 §9.3 파괴적 다이얼로그 경유. **적용취소 버튼·토스트 액션 제공 금지** (있는 척 금지).

**Do**: 적용취소 실행 후에도 토스트로 결과 통지 ("병합을 취소했습니다").
**Don't**: 적용취소를 빨간색/danger로 칠하기 — 이건 안전장치지 위험 동작이 아니다.

## §11 토스트 체계 v2

### 11.1 종류 확정 — 4종
| kind | 배경 | 보더 | 아이콘 | 용도 |
|---|---|---|---|---|
| success | `#1E2E14` | `rgba(78,104,52,.45)` | 체크 | 완료 통지 |
| error | `#5A1A10` | `rgba(160,60,46,.5)` | X원형 | 실패. **수동 닫기 버튼 항상 포함** |
| info | `--ink` #3D2418 | 없음 | i원형 | 안내·부가 설명 (신규 규정) |
| urgent | `--tc-d` #7C2D26 | `rgba(160,60,46,.5)` | !원형 | 연체 등 즉시 조치 |

- v1.2의 **warn 폐기**. 미납 안내→info, 연체→urgent로 흡수. 근거: 코드에 미구현 + warn/urgent 구분 기준이 모호했음.
- 텍스트 13px `#FBF6EF`. 아이콘 14px stroke 2.5.

### 11.2 위치·크기
- **하단 중앙 고정** (정중앙 폐지 — 콘텐츠와 마우스 동선을 가린다).
  `bottom: calc(var(--toast-offset-bottom) + env(safe-area-inset-bottom))`.
- 최대 폭 `--toast-w-max` 420px / 모바일 `calc(100vw - 32px)`. radius r-lg 10px, 패딩 10px 16px.
- 등장: translateY(12px→0)+opacity 200ms. 퇴장: opacity 150ms.

### 11.3 장문(결과+부가 설명)형
- 2줄 구조: **1행** 결과 13px/600, **2행** 부가 설명 12.5px/400 `rgba(251,246,239,.75)`, lh 1.55, 최대 3줄.
- 금액·일수는 tnum 숫자: "퇴실일 변경으로 일할 정산을 재계산했습니다 — `19일치 253,333원`".
- 지속: `--toast-dur-long` 5200ms. 1줄형은 2400ms.

### 11.4 액션 버튼 (적용취소 수용)
- 우측 끝 텍스트 버튼: 13px/700, 색 `--sand` #F2D9B8, 밑줄 없음, hover 밑줄.
- 히트 영역 44×44px 보장 (패딩으로 확장). 지속 `--toast-dur-action` 6000ms, **hover 중 타이머 일시정지**.

### 11.5 스택
- 동시 최대 **3개**, 신규가 아래·기존은 위로 밀림, 간격 8px. 4번째 도착 시 최고(最古) 즉시 퇴장.
- 동일 메시지 연속 발생 시 새 토스트 대신 기존 토스트에 카운트 배지 (`×2`).

**Do**: 저장·전환 등 "조용한 성공"은 1줄 success 2400ms로 짧게.
**Don't**: 토스트로 에러 상세를 길게 설명 — 3줄 초과면 토스트가 아니라 다이얼로그/인라인 에러다.

## §12 레이어(z-index) 위계

토큰표는 상단 CSS 블록 참조. 운영 규칙:

| 규칙 | 내용 |
|---|---|
| 토큰 외 z값 금지 | 임의 숫자(10/20/60/210…) 전부 토큰으로 교체. 형제 간 정렬은 z 없이 DOM 순서로 |
| 모달 중첩 | 최대 3중. 각 모달은 자기 backdrop을 가짐 (누적 어둠 자연 발생, 추가 어둡기 보정 금지) |
| Esc | **최상단 레이어만** 닫는다 (기 구현 — 명문화). confirm > modal-3 > modal-2 > modal 순 |
| 토스트 | 모달·라이트박스 위에서도 보인다 (400) |
| 브랜드 로더 | 라우트 전환 중 전 레이어 차단 (500) |
| 드롭다운 | 모달 내부 드롭다운은 `--z-dropdown`이 아니라 **부모 모달 z + 1** (portal 시 주의) |

## §13 폼 입력 표준

### 13.1 단일 스펙 (radius 혼용 4종 → 1종)
| 항목 | 값 |
|---|---|
| radius | **`--input-radius` 6px** — 텍스트·셀렉트·날짜·금액·textarea 전부 |
| 높이 | 40px / 모바일(<768px) 44px. textarea min 80px |
| 패딩 | 9px 13px |
| 폰트 | 13.5px Pretendard / 금액·숫자 입력은 Pretendard + tnum (사선 없는 0) |
| 기본 보더 | 1.5px `--border-s`, bg `--cream-2` |
| 포커스 | 보더 `--tc` + ring `0 0 0 3px rgba(160,60,46,.12)` |
| placeholder | `--ink-m` |
| 에러 | 보더 `--tc` + 하단 11px `--tc-d` 메시지 (ring은 포커스 시만) |
| 라벨 | 12px/500 `--ink-s`, 입력과 5px 간격 |

6px 선택 근거: v1.2 radius 토큰표가 이미 "r-sm 6 — 입력·배지"로 규정했고 코드 다수파(176곳)와 일치 — 마이그레이션 최소. v1.2 컴포넌트 데모의 8px 표기는 **본 문서로 정정**.

### 13.2 모달 내 폼 — 입력 유실 방지 정책
- **dirty(입력 시작) 후 배경클릭 무시**. Esc·X버튼은 ①일반 확인 다이얼로그 경유: "작성 중인 내용이 있습니다. 닫을까요?" — [계속 작성](primary) / [닫기](ghost).
  근거: 배경클릭은 대부분 오조작, Esc·X는 의도적 — 의도적 닫기에만 1회 확인.
- pristine(미입력) 상태에선 v1.2 규칙대로 모두 즉시 닫힘.

### 13.3 특수 입력
| 패턴 | 스펙 |
|---|---|
| 자동 합산(읽기전용) | bg `--sand-s`, 보더 없음, tnum 숫자, 우측 캡션 배지 "자동 계산" 10.5px `--ink-m`. 포커스 불가 |
| 상호배타 그룹 | 체크박스 금지 → **세그먼트 컨트롤** (radio): 높이 36px, 선택 bg `--cream` + 보더 `--tc`, 비선택 bg `--cream-2` |
| 임시저장 표시 | 폼 헤더 우측 칩: 점(6px `--success`) + "임시저장됨 14:32" 10.5px `--ink-m`. 저장 중엔 점이 `--camel` + "저장 중…" |

**Do**: 금액 입력엔 ₩ prefix 고정 표시 (v1.2 데모 방식 유지).
**Don't**: 한 폼 안에서 입력 높이 혼용 (인라인 검색창 등 예외는 36px sm 단일 허용).

## §14 상태·색상 확장

### 14.1 데이터 시각화 팔레트 (보라·블루·그린 hex 12종 전면 교체)
`--viz-1`~`--viz-8` (상단 토큰 블록). 사용 규칙:
- 차트 시리즈는 **viz-1부터 순서대로** 배정 — 화면마다 색 순서 재배치 금지.
- 인접 시리즈 구분이 어려울 땐 색 건너뛰기 허용 (1,3,5…), 순서 역전은 금지.
- KPI 카드 수치 색은 viz 금지 — v1.2 규칙(기본 `--ink`, 강조 `--tc`, 긍정 `--success`)만.
- raw Tailwind 팔레트(red/emerald/blue/purple/indigo) 및 자체 hex **사용 금지**.

### 14.2 상태 5단계 적용 범위 (전면 통일)
PAID/AWAIT/UNPAID/OVERDUE/VACANT 토큰은 **수납 표·호실 카드·대시보드 방현황·알림 행·필터 칩** 전부에서 동일 적용. 대시보드라고 별도 색 체계 금지 — **대시보드에 OVERDUE 단계 추가 필수** (현재 누락). 상태색을 차트에 쓸 땐 상태 토큰 그대로 사용 (viz 팔레트로 대체 금지 — 의미가 색에 있다).

### 14.3 뱃지 병렬 패턴
- 순서: **수납 상태 먼저, 일정 상태 뒤** ([미납] [퇴실 예정]). 간격 4px, 최대 2개.
- 3개 이상 필요하면 2개 + "+1" 뉴트럴 뱃지.
- 보조줄: 뱃지 아래 10.5px `--ink-m`, 구분자 ` · ` — "12일 초과 · 6/13 퇴실 D-3". D-day·일수는 tnum 숫자.

#### 6개 결정 — 답 + 근거

1. **danger 빨강 → ⒜ 테라코타로 흡수.** 별도 적색 hue 신설 안 함. 근거: 이 브랜드에서 경고·위험은
   이미 테라코타가 담당(OVERDUE·미수·파괴적 확인 §9가 모두 terracotta solid). 새 red는 무지개 복원이다.
   - 삭제 버튼: **soft 스타일**(`--danger-bg` + `--danger-fg`, btn-danger) — primary(solid terracotta)와 채움/외곽으로 구분, 색상 hue로 구분하지 않는다.
   - 파괴적 확인 버튼: solid `--danger-solid`(=terracotta) — §9 규칙 유지. 구분은 아이콘·동사 라벨·영향목록이 담당.
   - 에러 박스: bg `--danger-bg`, border `--danger-ring`, text `--danger-fg`. (시스템 실패 토스트는 §11의 deep-wine 배경 유지.)
2. **success 초록 → 올리브 단일.** 완납·비결제 긍정("연결됨"·"저장됨") **모두 `--success-*`**. 근거: 긍정 hue는 하나만 — emerald 분리는 무지개 복원. "저장됨"은 §11 success 토스트로도 처리.
3. **amber → 단일 `--warning-*`.** 미납·경고·변동 플래그 한 토큰 공유. 근거: 셋 다 "주의 필요·아직 비위기"로 동일 위계(§11에서 warn 흡수와 일관). 분리하면 같은 노랑 두 토큰이 생겨 혼란.
4. **deposit 보라 → 카멜 / reserve teal → 토프.** 라이트값도 확정 교체(현재 라이트 보라·teal 폐기).
   deposit=보관된 돈→웜 카멜(`--deposit-*`), reserve=미래 점유→중립 토프(`--reserve-*`, 카멜과 명도·채도로 구분). 근거: 둘 다 액센트일 뿐 무지개일 이유 없음. viz 팔레트와 동계열.
5. **blue 정보·양도인 → `--info-*`로 await와 통합(동일 hex).** 근거: 쿨 액센트는 블루 1종만 허용. await(상태)·info(범용)·양도인은 의미 별칭으로 두되 색은 하나. 구분은 라벨·맥락.
6. **페일 틴트 3종 → bg/fg/ring 트라이어드로 1:1.** `bg-{50}→--{semantic}-bg` · `text-{700}→--{semantic}-fg` · `ring-{200}/border-{200}→--{semantic}-ring`.

#### ⚠️ 다크 리매핑 함정 — solid vs text 분리

`--success-fg`·`--*-fg`는 다크에서 **밝은** 값으로 뒤집힌다(#4E6834→#A3BF7B). 이 밝은 값을
**흰/cream 글자 솔리드 배지 배경**에 쓰면 대비가 붕괴한다. 그래서 **`-solid`는 다크에서도 깊은 값 고정**(⛔):
- 솔리드 배지/버튼 배경 = `--{semantic}-solid`(깊은 값, 양 모드 동일) + cream 글자.
- 틴트 칩·인라인 텍스트·아이콘 = `--{semantic}-fg`(다크에서 밝아짐) + 투명 틴트 bg.
- 절대 `--success-fg`(밝은 올리브)를 솔리드 배지 bg로 쓰지 말 것 — 완납 솔리드 배지는 `--success-solid` #4E6834.

#### Tailwind → 토큰 치트시트

| raw | → 토큰 | raw | → 토큰 |
|---|---|---|---|
| `text-red-500/600` #ef4444·#dc2626 | `--danger-fg`¹ | `bg-red-50` | `--danger-bg` |
| `ring-red-200` `border-red-200` | `--danger-ring` | `bg-red-500`(solid btn) | `--danger-solid` |
| `text-emerald-500/green-600` #22c55e·#16a34a | `--success-fg` | `bg-emerald-50` | `--success-bg` |
| `text-amber-500/yellow-600` #eab308·#f59e0b | `--warning-fg` | `bg-amber-50` | `--warning-bg` |
| `text-blue-500/sky/indigo` #3b82f6 | `--info-fg` | `bg-blue-50` | `--info-bg` |
| `text-purple-500/violet` #a855f7·#7c3aed | `--deposit-fg` | `bg-purple-50` | `--deposit-bg` |
| `text-teal-500/cyan` #0d9488 | `--reserve-fg` | `bg-teal-50` | `--reserve-bg` |

¹ 단, **연체** 강조는 `--overdue-fg`, **미수(음수 금액)**는 §15 규칙(`--danger-fg`)로 — 둘 다 hue는 같다.

**Do**: raw 무지개색은 1:1 토큰 치환만 — 의미가 모호한 곳은 치환 멈추고 보고.
**Don't**: 새 hue 추가 / `-fg`(밝은 다크값)를 솔리드 배지 배경에 사용 / 라이트에서 의도된 픽셀 변경.

#### 14.4b 정합 확인 — 컴포넌트 리터럴 2건 (2026-07-02)

코드 감사에서 발견된 리터럴 잔존의 정본 처리. **신규 토큰 만들지 않는다** — 기존 §14.4 토큰으로 흡수.

**① Badge 'pale-green' 쌍 (`bg #eef2e5 + text #4e6834`, 라이트·다크 동일)**
- 정본: `bg → --success-bg` · `text → --success-fg` (**둘을 항상 쌍으로 이동**, text만 토큰화 금지).
- 근거: 이건 **틴트 칩**(솔리드 배지 아님)이므로 다크에서 `-fg`가 밝아지는 게 정상 동작(§14.4 함정의 "틴트 칩" 케이스). bg·fg가 함께 다크 변환(#eef2e5 불투명 → `--success-bg` rgba 반투명 / #4e6834 → #A3BF7B)되어 대비 유지.
- **Don't**: text만 `--success-fg`로 바꾸고 bg는 #eef2e5 불투명 고정 → 다크에서 밝은 배경+밝은 글씨로 붕괴(이번 우려 지점).

**② StatusBadge ROW_TINT 6종 (rgba 리터럴, 주석 "라이트·다크 공용")**
- 정본: "라이트·다크 공용" 의도는 **폐기** → 각 의미의 `--{semantic}-bg`로 전환(다크 자동 변형). §19.1 다크 배지 배경표가 이미 의미별 다크 틴트를 따로 규정하므로 "공용"과 충돌.

  | ROW_TINT | → 토큰 | 다크 의도값(참조 §19.1) |
  |---|---|---|
  | 완납/PAID | `--success-bg` | rgba(163,191,123,.14) |
  | 예정/AWAIT | `--info-bg` | rgba(147,169,209,.14) |
  | 미납/UNPAID | `--warning-bg` | rgba(217,166,72,.14) |
  | 연체/OVERDUE | `--danger-bg`* | rgba(224,138,117,.12) |
  | 보증금/deposit | `--deposit-bg` | rgba(212,180,148,.14) |
  | 공실/VACANT | `--neutral-bg` | rgba(242,232,220,.06) |

  \* 연체 행은 `--danger-bg`(테라코타 hue, danger=terracotta 흡수) + **좌측 3px `--overdue-fg` 보더**가 강조를 담당 → 행 채움은 옅게. §14.4에 별도 `--overdue-bg`는 두지 않음(중복 hue).
- **Do**: 행 틴트는 `-bg`(반투명, 다크 자동). **Don't**: 불투명 rgba를 전 모드 고정으로 박기.

### 18.1 로딩 상황 결정표 — 상황당 패턴 정확히 1개

**Don't**: 스켈레톤 + 브랜드 로더 동시 발동 — 어떤 조합으로도 금지.

### 18.2b 콜드 부트 인트로 시퀀스 (v1.3.2 신규)

콜드 부트(①·⑥)의 스플래시는 루프형 로더가 아니라 **1회성 인트로**를 재생한다.
"로딩을 견디는 화면"이 아니라 "브랜드가 자기소개하는 3.2초"다 — 영문과 국문 이름을 차례로 보여준다.

| 구간 | 시간 | 동작 |
|---|---|---|
| draw | 0 – 1.0s | 아치 한 획 line-draw (왼→오른쪽, cubic-bezier(.65,0,.35,1)) |
| lockup EN | 1.0 – 1.4s | 디바이더 + 영문 워드마크(stayeum) 페이드인 |
| hold EN | 1.4 – 2.0s | 영문 락업 정지 |
| swap KO | 2.0 – 2.35s | 영문 → 국문(스테이음) 크로스페이드 |
| hold KO | 2.35 – 3.2s | 국문 락업 정지 — 시각적 안착 |
| exit | max(3.2s, 앱 준비) | 400ms 크로스페이드로 홈에 양보 |

- **완주 보장**: 앱이 3.2s보다 먼저 준비돼도 인트로는 끊지 않는다. `--splash-intro` 3200ms 완주 후 퇴장. (18.3의 --loader-delay·--loader-min·중단 허용 규칙은 인트로에 미적용 — 유일한 예외)
- **지루함 방지**: 인트로 전체 재생은 **브라우저 세션당 1회** (sessionStorage `sy-intro-seen`). 같은 세션 내 새로고침·재진입은 인트로 생략하고 18.3 임계(300ms/1000ms) 적용. 근거: 첫 만남은 의식, 반복은 도구.
- 인트로 종료 후에도 로딩 중이면: 락업 유지 + 3.2s마다 KO↔EN 크로스페이드(KO에서 이어받음), 5s 초과 시 느린 연결 캡션(18.2).
- **클리핑 주의**: 아치 stroke(두께 20)는 viewBox(0 0 130 100)를 벗어난다 — svg에 `overflow: visible` 필수. 없으면 상단·양끝이 잘린다.
- prefers-reduced-motion: 인트로 생략 — 정적 락업(EN) 즉시 표시, 준비되면 크로스페이드만.
- 레퍼런스 구현: `stayeum Splash Intro.html` (데모 — 일반/느린 연결 시뮬레이션 포함)

**Do**: 인트로 중에도 앱 데이터 prefetch는 백그라운드로 진행 — 인트로는 기다림이 아니라 병행.
**Don't**: 인트로에 스킵 버튼 — 2.4s는 스킵 UI가 더 방해되는 길이다.

### 18.3 타이밍 임계 — 깜박임 방지

- **표시 지연**: 전환·로딩이 `--loader-delay` 300ms 안에 끝나면 로더·스켈레톤 모두 미표시. (스켈레톤도 동일 임계 적용 — 빠른 전환에서 shimmer 한 프레임 깜박 방지)
- **최소 유지**: 한번 보였으면 `--loader-min` 1000ms 유지 후 퇴장. 근거: 브랜드 로더 첫 획(line-draw)이 완성되는 시점이 1.0s — 의미 단위가 끝난 뒤 사라진다.
- **사이클 정수배 대기 금지**: 3.2s 완주를 기다리지 않는다. 1.0s 이후에는 언제든 200ms 페이드아웃으로 중단 허용 — 체감 속도가 모션 완결성보다 우선.
- **예외**: 콜드 부트 인트로(18.2b)는 본 임계의 적용을 받지 않는다 — 세션 첫 1회는 2400ms 완주.

**Don't**: delay 없이 즉시 표시 — 300ms 미만 전환이 전체의 다수다.

### 18.4 FOUC 방어 — 첫 페인트 이전

- `index.html` 인라인 critical CSS (외부 CSS보다 앞에):
  ```html
  <style>html{background:#E8DDD0}@media(prefers-color-scheme:dark){html{background:#000000}}</style>
  <meta name="theme-color" content="#E8DDD0" media="(prefers-color-scheme: light)">
  <meta name="theme-color" content="#000000" media="(prefers-color-scheme: dark)">
  ```
- 흰 화면(#fff) 노출 0ms — HTML 도착 순간부터 브랜드 배경.
- 다크모드 감지는 CSS 미디어 쿼리로만 (JS 감지 전 깜박임 원천 차단). JS 테마 설정은 이후 덮어쓰기만.

### 18.6 PWA 3단계 연속성

| 단계 | 화면 | 규정 |
|---|---|---|
| 1 · OS 스플래시 | manifest background + 아이콘 | background **#E8DDD0 = --page 일치 강제** · theme #A03C2E · 아이콘은 테라코타 바탕 앱 아이콘 |
| 2 · 웹 스플래시 | 18.2 | 배경 동일→아이콘 자리에 브랜드 로더가 이어받음 (위치 유사, 점프 최소화) |
| 3 · 앱 셸 | ② 크로스페이드 | 배경이 --page로 동일하므로 색 교체 0회 |

- 점검 기준: `--page` 토큰 값 변경 시 manifest background도 동일 커밋에서 변경 — 불일치는 릴리즈 블로커.
- 다크모드 PWA: manifest는 단일값만 허용하는 OS가 있으므로 라이트 값 유지, 웹 스플래시(2단계)부터 다크 적용.

**Do**: 앱 아이콘·OS 스플래시·웹 스플래시의 로고 크기를 시각적으로 비슷하게 — 점프 감소.
**Don't**: 웹 스플래시 배경을 --cream이나 브랜드 컴러로 — OS 스플래시와 색이 달라 깜박임이 생긴다.

## §20 인쇄 서류 (Print Documents)

> **범위**: 앱이 발급하는 A4 PDF 서류 전체 — 계약서·입실료 납부 확인서·각종 확인서·정산서·안내문.
> §09~§19가 "화면 UI"라면 §20은 "종이로 나가는 것"의 단일 출처다. 화면 토큰을 그대로 쓰지 않고
> **인쇄 전용 토큰(`--p-*`)**을 별도로 둔다 — 종이/복사/팩스/관공서 제출 맥락은 화면과 요구가 다르다.
> 공문서(정부 원본 양식)는 **건드리지 않는다** — §20.7의 브랜딩 OFF 규칙만 적용.

### 20.0 설계 원칙

| 원칙 | 내용 |
|---|---|
| 본문은 먹1색 | 본문·표·라벨은 모두 단색 잉크(`--p-ink`). 컬러는 **헤더 룰·금액 강조·워드마크**에만 |
| 진중함 우선 | 라운드 코너·그림자·이모지·일러스트 금지. 직각·hairline·정렬로 신뢰를 만든다 |
| 위·변조 저항감 | 발행번호·발행일시·영업장 사업자정보·도장 영역을 항상 노출 — "비어 보이지 않게" |
| 흑백 출력 안전 | 테라코타가 흑백 복사 시 회색이 돼도 정보가 죽지 않게 — 색은 보조, 위계는 굵기·크기·선으로 |
| 좌표 이식성 | 모든 수치는 mm/pt. pdf-lib가 좌표로 바로 옮길 수 있게 |

### 20.1 표준 폰트 (임베드 가능 TTF 1종)

| 항목 | 결정 | 근거 |
|---|---|---|
| 표준 본문 | **Pretendard TTF** (static .ttf, GitHub 릴리스 제공) | 제품 UI와 동일 가족 → 브랜드 연속성. woff2 임베드 불가 문제를 static TTF가 해결 |
| 웨이트 | Regular 400 / Medium 500 / SemiBold 600 / Bold 700 — **4종만 임베드** | 파일 크기 절제. pdf-lib는 웨이트별 별도 TTF 임베드 |
| 폴백 | **NanumGothic** (현행) | 공문서 오버레이 등 중립 맥락 / Pretendard 미가용 환경 |
| 숫자 | Pretendard 숫자 사용. tnum OpenType 피처는 pdf-lib에서 자동 적용 안 됨 → **표·금액은 우측 정렬**로 자릿수 정렬 보장 (§15 tnum 정신 계승) | pdf-lib는 GSUB/GPOS 피처 미적용. 정렬은 좌표로 해결 |

**Do**: 서류 1건 = 임베드 폰트 1가족(Pretendard TTF) 고정.
**Don't**: 서류마다 폰트 바꾸기(현재 계약서 Pretendard / 영수증 나눔고딕 혼재가 문제) — 폴백은 미가용 시에만.

### 20.2 인쇄 전용 토큰 (`--p-*`)

```
/* 색 — 화면 토큰과 분리. 인쇄/복사 안전값 */
--p-ink:         #1F1A17;   /* 본문·표·라벨 (먹1색, 웜 니어블랙) */
--p-ink-muted:   #6B5D4F;   /* 주석·메타·라벨 보조 */
--p-tc:          #A03C2E;   /* 헤더 룰·금액 강조·워드마크 전용 */
--p-label-bg:    #F2ECE3;   /* 표 라벨열 음영 (웜 그레이) */
--p-rule:        #D8CFC4;   /* 표 hairline·구분선 */
--p-rule-strong: #9A8A78;   /* 표 외곽·헤더 하단 보조선 */
--p-paper:       #FFFFFF;   /* 용지 = 순백 (인쇄는 #fff 허용 — 화면 규칙과 별개) */

/* 지면 — A4 210×297mm */
--p-margin-x:    20mm;      /* 좌우 여백 */
--p-margin-top:  18mm;
--p-margin-bot:  20mm;      /* 푸터 워드마크 공간 확보 */
--p-content-w:   170mm;     /* 210 − 2×20 */

/* 선 두께 (pt) */
--p-hairline:    0.4pt;     /* 표 내부 셀 선 */
--p-rule-w:      0.6pt;     /* 표 외곽·박스 */
--p-header-rule: 1.6pt;     /* 헤더 하단 테라코타 룰 */
```

### 20.3 타입 스케일 (pt)

| 역할 | 크기/웨이트 | 색 | 비고 |
|---|---|---|---|
| 문서 제목 | 20pt / 700 | `--p-ink` | 예 "입실료 납부 확인서" · 자간 −2% |
| 발행 메타 | 9pt / 400 | `--p-ink-muted` | 발행번호·발행일 (제목 우측 정렬) |
| 섹션 소제목 | 12pt / 600 | `--p-ink` | 좌측 3pt 테라코타 탭 선택 |
| 표 라벨 (키) | 10pt / 500 | `--p-ink` | 라벨열, `--p-label-bg` 배경 |
| 표 값 | 10.5pt / 400 | `--p-ink` | 값열 |
| 금액 강조 | 15pt / 700 | `--p-tc` | ₩ 포함, 우측 정렬 |
| 본문/안내문 | 10.5pt / 400, 행간 1.6 | `--p-ink` | |
| 주석·단서 | 8.5pt / 400 | `--p-ink-muted` | 하단 단서·법적 문구 |
| 푸터 워드마크 | 8pt | "made with " `--p-ink-muted` + "stayeum" `--p-tc` | §20.6 |

**최소 크기**: 인쇄 본문 ≥ 8.5pt (가이드 인쇄 최소). 8pt는 푸터·법적 주석만.

### 20.4 그리드 · 표 · 키-값 행

- **A4 그리드**: 단일 컬럼, 콘텐츠 폭 170mm. 2분할 필요 시 좌우 각 82mm + 6mm 거터. (영수증은 **A5** — §20.10(a), 콘텐츠 폭 120mm)
- **키-값 행 (가장 흔한 단위)**:
  - 라벨열 폭 **40mm**, 값열 나머지. 행 높이 **9mm**, 수직 중앙.
  - 라벨열 배경 `--p-label-bg`, 라벨 10pt/500. 값 10.5pt/400, 좌패딩 4mm.
  - 행 구분선 `--p-hairline` `--p-rule`. 표 외곽 `--p-rule-w` `--p-rule-strong`.
- **데이터 표**: 헤더행 `--p-label-bg` + 10pt/600, 데이터행 높이 8mm, 금액 컬럼 **우측 정렬**.
- **셀 패딩**: 좌우 4mm, 상하 2mm. 숫자·금액은 우측 정렬, 텍스트는 좌측.

**Do**: 라벨은 라벨열(음영)에, 값은 값열에 — 키-값을 시각적으로 분리.
**Don't**: 표에 세로선 남발 — 가로 hairline 위주, 세로선은 라벨/값 경계 1개만.

### 20.5 헤더 — 영업장 정체성

```
[로고 PNG 14mm 정사각]  영업장명 (14pt/700)              발행번호 No. (9pt, 우측)
                        사업자등록번호·대표자 (9pt/400)    발행일 (9pt, 우측)
                        주소·전화 (9pt/400 --p-ink-muted)
──────────────────────────────────────────────────  ← 테라코타 룰 1.6pt
```
- 헤더 밴드 높이 **22mm**. 로고(투명 PNG)는 좌측 14×14mm, 없으면 워드마크 텍스트 대체.
- 하단 **테라코타 룰 1.6pt**(`--p-tc`)이 헤더와 본문을 가른다 — 서류의 시그니처.
- 영업장명은 businessInfo에서, 로고/도장은 자산 PNG. 사업자정보는 위·변조 저항감의 핵심이라 항상 노출.

### 20.6 푸터 · 워드마크

- 위치: 하단 여백 내 중앙 또는 우측, baseline이 용지 하단에서 **12mm**.
- 형식: "made with " (`--p-ink-muted` 8pt) + "stayeum" ("stay" `--p-ink` / "eum" `--p-tc`, 8pt/600).
- 페이지 번호: **2페이지 이상 서류에만** 좌측 하단 "1 / 2" 8pt `--p-ink-muted`. **단일 페이지 영수증 등은 생략**(불필요한 정보 제거).

### 20.7 브랜딩 ON / OFF 경계

| 구분 | 서류 | 브랜딩 |
|---|---|---|
| **OFF (중립)** | 정부 원본 양식 위 데이터 오버레이 (실거주 확인서 등 공문서) | 워드마크·테라코타·로고 **금지**. 채워 넣는 글자는 양식 폰트(나눔고딕)에 맞춰 먹1색만. stayeum 흔적 없음 |
| **ON (풀 브랜딩)** | 자체 제작 서류 (영수증·정산서·안내문·자체 확인서) | §20.5 헤더 + §20.6 푸터 워드마크 + 테라코타 강조 전부 적용 |
| **혼합** | 자체 계약서 | 풀 브랜딩 가능하나 본문 가독성 우선 — 강조는 금액·당사자명 룰에만 절제 |

**경계 기준**: "이 양식의 레이아웃을 우리가 정하는가?" → 예면 ON, 정부/제3자 고정 양식이면 OFF.
**Don't**: 공문서에 워드마크·테라코타 삽입 — 관공서 제출 시 위화감·반려 위험.

### 20.8 발행 메타 · 날짜 · 금액 포맷

| 항목 | 형식 | 예 |
|---|---|---|
| 발행번호 | `No. YYYYMMDD-NNN` (영업장별 일련) | No. 20260616-014 |
| 발행일 | `YYYY년 M월 D일` | 2026년 6월 16일 |
| 거주기간 | `YYYY.MM.DD ~ YYYY.MM.DD` | 2026.01.15 ~ 2026.07.14 |
| 금액 (본문) | `₩` + 천단위 쉼표, **축약 금지** (§15 법적 맥락) | ₩450,000 |
| 금액 (한글 병기) | 큰 금액은 한글 병기 권장 | 금 사십오만원정 (₩450,000) |
| 음수(환불·감액) | `−` U+2212 + `--p-tc` | −80,000원 |

### 20.9 서명 · 도장 영역

- 영역: 본문 하단, 우측 정렬. "임대인 (영업장명)" 라벨 + 성명 + **(인)** 표기.
- **도장 PNG**가 있으면 "(인)" 글자 위에 도장 이미지를 **18×18mm**로 중앙 오버레이 (글자가 비쳐도 무방 — 실제 날인 모사).
- 서명란 폭 60mm, 우측 정렬. 수령인(입주자) 서명란이 필요한 서류는 좌측에 대칭 배치.
- **도장-문구 간섭 방지**: 도장(18mm)은 중심에서 위·아래 9mm를 차지하므로, "(인)"이 있는 서명줄과 그 위 확인 문구 사이에 **최소 11mm 수직 여백**을 둔다 — 도장 상단이 문구를 가리지 않게.

**Do**: 도장은 (인) 위치를 덮도록 — 실제 날인처럼.
**Don't**: 도장 이미지를 헤더 로고로 재사용 — 용도가 다르다(로고=정체성, 도장=날인).

### 20.10 문서별 레이아웃

#### (a) 입실료 납부 확인서 — 자체 양식 · 풀 브랜딩 · pdf-lib · **A5(148×210mm) 기본**
> 명칭: 구 "월세 영수증" → **"입실료 납부 확인서"**. 용지: 영수증·확인서는 **A5 세로** 표준 (실무 관행). 여백 좌우 14mm·상 12mm·하 14mm, 콘텐츠 폭 120mm.
> 타입은 A4 스케일에서 한 단계 축소: 제목 17pt · 영업장명 12pt · 라벨 9pt/값 9.5pt · 금액 14pt · 라벨열 34mm · 행 8mm · 헤더밴드 18mm · 로고 12mm. (계약서·정산서 등 본문량 많은 서류는 A4 유지.)
```
헤더(22mm): 로고 | 영업장명·사업자정보 | No.·발행일 + 테라코타 룰
제목: "입실료 납부 확인서" 17pt/700 (A5)
키-값 블록 (라벨열 34mm):
  수령인(입주자) · 호실 · 거주기간 · 납부 대상월
금액 박스: "영수 금액" 라벨 + ₩450,000 15pt/700 테라코타 우측 + 한글 병기
키-값: 납부일 · 납부방법(현금/계좌) · 비고
서명/도장: 우측 "임대인 (영업장명) 대표 ○○○ (인)" + 도장 PNG
푸터: made with stayeum 워드마크
```
#### (b) 임대차·입실 계약서 — 자체 양식 · 혼합 · puppeteer 유지 가능
- 다중 페이지. 헤더는 1p만 풀, 2p~ 간략(영업장명 + 페이지번호). (조항이 적으면 A4 1p 가능 — 레퍼런스 `stayeum 입실계약서 템플릿.html`)
- 조항은 번호 목록 10.5pt 행간 1.7. 당사자 정보·금액은 키-값 표.
- 강조 절제: 보증금·월세 금액과 당사자명만 `--p-tc` 룰/굵기. 조항 본문은 먹1색.
- 말미 당사자 서명·도장 영역(임대인·임차인 대칭).
- **조항은 영업장별로 다름 → 데이터 분리 필수.** 조항 제목·항목·서약문은 `CONTRACT_CONFIG`(또는 영업장 DB) 객체에서 주입하고, 레이아웃/스타일은 고정. 강조는 본문 안에서 `**…**` 마커로 표기 → 렌더 시 `--p-tc` 강조로 변환(핵심 조건만). 개발은 이 구조를 영업장 설정에서 읽어 동일 디자인으로 렌더.
- **한글 줄바꿈**: 인쇄 서류 본문은 `word-break: keep-all` 적용 — 좁은 단에서 "선/납"처럼 어절 중간이 끊기는 것을 방지(어절 단위 줄바꿈).

#### (c) 실거주 확인서 — 정부 원본 · 브랜딩 OFF · 오버레이
- 양식 픽셀 변경 금지. 좌표 오버레이로 데이터만 기입(나눔고딕 먹1색).
- stayeum 헤더·푸터·테라코타 **삽입 안 함**. §20은 이 문서엔 "기입 글자 정렬·크기"만 관여.
- 기입 텍스트 10pt 내외, 칸 중앙. 날짜·성명·주소는 양식 칸 좌표에 맞춤.

## §21 재고·리스트 컴포넌트 (Inventory & List Components)

> 재고관리(소모품·부식 / 비품·자재) 화면 통일에서 추출한 **공용 컴포넌트 5종**. 데이터 성격이
> 다른 두 탭이 동일 화면 문법을 쓰도록 한다. 리스트형 화면(알림·정산 항목 등) 전반에 재사용 가능.

### 21.1 InventoryCard — 카드 해부구조 (정본)

하나의 골격에 데이터만 교체한다. 좌(정체성) · 우(핵심 수치 1개) · 하단(액션 행) · 옵션(펼치기).

```
[✓체크]  제목 + 뱃지            ← 핵심 수치 1개
         메타(규격·예측 등)        보조(최소/금액)
─────────────────────────────  ← 1px --border
[ 액션1 ] [ 액션2 ]              ← 동일 높이 34px
```

| 요소 | 값 |
|---|---|
| 컨테이너 | bg `--cream` · border 1px `--border` · radius 13px · padding 13/14px |
| 선택 상태 | `.sel`: border `--tc` + ring 2px rgba(160,60,46,.16) |
| 주의 강조 | `.attn`: border-left 3px `--tc` (소진 임박·연체 등) |
| 제목 | 14.5px / 600 / −.015em, 뱃지 inline (gap 6px) |
| 메타 | 11.5px `--ink-m` |
| 핵심 수치 | DM Mono 19px / 700, 우측. 위험 시 `--tc`. 단위 11px `--ink-m` |
| 액션 행 | 상단 1px `--border` 구분, 버튼 height 34px radius 8px, 주 버튼 1개만 solid `--tc` |
| 체크박스 | 22px radius 7px, on=`--tc`+흰 체크 (선택 모드에서만 노출) |
| 펼치기 | 1px `--border` 구분 후 11.5px 행(합산·구매 N건·이력 요약) |

- **수치 슬롯은 항상 1개.** 소모품=현재고/개, 비품=수량(+금액 보조). 두 개 이상의 수치는 펼치기/상세로.
- **Do**: 탭이 달라도 같은 골격 — 마커·수치·액션 라벨만 교체. **Don't**: 탭마다 카드 레이아웃을 새로 짜기.

### 21.2 SectionHeader — 마커 슬롯형 그룹 헤더

그룹 축(소모품=카테고리, 비품=배정 위치)은 다르되 **마커만 교체**하고 나머지는 동일.

| 요소 | 값 |

| 이름 | 13px / 700 `--ink` |
| 카운트 | DM Mono 11px `--ink-m` |

- **Do**: 마커 색·아이콘만 데이터로. **Don't**: 축이 다르다고 타이포·간격·카운트 위치를 바꾸기.

### 21.3 SelectionPillBar — 선택 모드 하단 알약

화면 하단 floating 다크 알약. **탭별 가능한 액션만** 노출하되 컴포넌트는 동일.

| 요소 | 값 |
|---|---|
| 컨테이너 | bg `--ink` · radius 15px · left/right 14px · bottom 16px · shadow lg · z `--z-pill` (120) |

- **Do**: 불가능한 액션은 숨김(비활성 아님). **Don't**: 탭마다 다른 알약 디자인.

### 21.4 MergeSheet — 합치기 단일 바텀시트

A의 상세 속 MergeSection·전용 규칙 모달과 B의 인라인 합치기를 **하나의 시트로 통일**.
카드 액션·상세·선택 알약 어디서 열어도 같은 컴포넌트.

| 요소 | 값 |
|---|---|
| 시트 | bg `--cream` · radius 20px(상단) · padding 8/18/20px · scrim rgba(31,26,23,.45) · z `--z-modal` (300) |
| 그립 | 38×4px `--border-s` 중앙 |

| 대상 선택 | select height 44px radius 10px bg `--cream-2` border 1.5px `--border-s` |
| 방향 확인 | `이 카드 → 남는/대표 카드` 박스, 화살표 `--tc` — 무엇이 사라지고 무엇이 남는지 명시 |
| 액션 | 취소(secondary) + 합치기(solid `--tc`, flex 1.6) height 46px |

- **방향 고지 필수**: 병합은 비가역이므로 "남는 카드"를 반드시 보여준다(§09 파괴적 확인 정신).
- **적용취소**: 실행 후 §10 undo 토스트로 되돌림 — 환경설정에 숨기지 않는다(단일 위치 원칙).
- **Do**: 모든 합치기 진입점이 이 시트로 수렴. **Don't**: 탭별로 다른 병합 UI.

### 21.5 상세 진입 · 적용취소 통일 규칙

- **카드 본문 탭 → 상세 풀화면**(이력·라벨 편집·합치기 한 곳). 양 탭 공통.
- **가벼운 합산**(구매 N건)은 카드 내 펼치기 토글로 즉시.
- **적용취소는 항상 §10 undo 토스트** — 위치·라벨·아이콘·지속시간 모두 §10 정본. "되돌릴 수 없는 동작"만 §09 다이얼로그.

## §24 뷰 전환 탭 (View Tabs)

> **계기**: "한 페이지 안에서 뷰를 갈아끼우는 탭"이 코드에서 3계열로 분열(A 코랄 채움 조인트 / B SegmentedControl 트랙 / C rounded-2xl 코랄 변종). 같은 의미가 화면마다 다른 컴포넌트 — §22.8 키 위반. §24는 **뷰 전환 탭의 단일 정본**을 세운다. **필터가 아니다** — §22.2 필터 SegmentedControl은 그대로 유지.

### 24.0 판별 기준 — 필터 vs 뷰 전환 탭 vs 링크 탭

먼저 "이 컨트롤이 무엇인가"를 판별한다. 셋은 **다른 컴포넌트·다른 외형**을 쓴다(혼용 금지).

| | 필터 (§22.2) | **뷰 전환 탭 (§24)** | 링크 탭 |
|---|---|---|---|
| 의미 | 같은 목록을 **좁힌다** | 같은 페이지에서 **다른 뷰/데이터셋으로 교체** | **다른 라우트로 이동** |
| 결과 | 행 수 감소, 열·레이아웃 동일 | 콘텐츠 구조가 바뀜 (다른 표·다른 KPI) | URL 변경, 페이지 전환 |
| '전체' 개념 | 있음(해제=전체) | **없음** — 항상 정확히 1개 활성 | 없음 |
| 컴포넌트 | SegmentedControl (트랙+떠있는 세그) | **ViewTabs (코랄 채움 조인트)** | ViewTabs 외형 + `<a href>` |
| 예 | 상태 빠른필터(전체/미납/완납) | 소모품↔비품, 지출↔자산↔보증금, 결산↔예상↔AI | 재고 탭(각 탭이 라우트) |

- **핵심 분리**: 필터는 **트랙형(cream 세그가 cream-2 트랙 위에 뜸)**, 뷰 전환은 **코랄 채움형**. 두 외형이 달라야 사용자가 "좁히기"와 "갈아끼우기"를 구별한다.
- **Do**: 활성이 항상 1개면 뷰 전환 탭. **Don't**: 뷰 전환에 '전체' 세그 추가 / 필터를 코랄 채움으로.

### 24.1 정본 계열 선택 — **A계열 (코랄 채움 조인트 탭)**

**결정: A를 정본으로, B의 role=tablist 접근성 세맨틱을 흡수한다. B·C의 뷰 전환 용도는 폐기.**

- **왜 A인가 (1)**: §22.2가 이미 트랙+떠있는 세그(B 외형)를 **필터**로 점유했다. 뷰 전환도 B를 쓰면 같은 화면에서 "필터인지 뷰 전환인지" 시각 구분이 사라진다 → A의 코랄 채움으로 역할을 분리.
- **왜 A인가 (2)**: 뷰 전환은 페이지 정체성 전환(소모품 사전 → 비품 사전)이라 무게·시인성이 필터보다 높아야 하며, 코랄 채움이 그 위계에 맞다.
- **B·C 폐기**: B(재무 TABS)·C(리포트 rounded-2xl)의 **뷰 전환 용도**는 A로 이관. B의 SegmentedControl 컴포넌트 자체는 **필터 전용**으로 계속 쓴다(폐기 아님). C의 rounded-2xl은 radius 토큰(§ radius) 이탈이므로 완전 폐기.
- **접근성 흡수**: A는 `<span>`/`<a>`로 세맨틱이 없었다 → 정본은 `role=tablist`/`role=tab`/`aria-selected`를 A 외형에 씌운다(24.6).

### 24.2 스펙 — 컨테이너 · 세그 · 상태

| 요소 | 값 |
|---|---|
| **컨테이너** | `inline-flex` · radius **10px (r-md)** · border 1px `--warm-border` · `overflow: hidden` · bg `--cream` · padding 0(세그가 꽉 채움) |
| **세그(탭)** | 높이 **최소 40px**(모바일 44pt는 24.6) · padding `10px 16px` · 타이포 14px/600 · radius 0(컨테이너가 라운드 소유) · 세그 사이 구분선 1px `--warm-border` |
| **탭 모드** | 기본 `내용탭(inline-flex)`. 2~3개를 균등 채움이 필요할 때만 `flex-1`(구 C의 유일한 장점 계승) |

| 상태 | 배경 | 텍스트 | 기타 |
|---|---|---|---|
| **활성** active | `--coral` | `--cream` (white 금지, §14) | `aria-selected=true` |
| **비활성** | `--cream` | `--warm-mid` | |
| **hover**(비활성) | `--cream-2` | `--warm-dark` | transition 150ms(§ 모션) |
| **focus-visible** | (배경 유지) | | outline 2px `--coral` offset 2px — §접근성 링 |
| **disabled** | `--cream` | `--warm-muted` | `cursor:not-allowed` · aria-disabled |

- 활성 세그는 다크모드에서도 `--coral`+`--cream`(전 모드 동일 값 계열) — `-fg` 반전 토큰 쓰지 말 것(§14.4 함정).
- **Do**: 활성=코랄 채움 1개. **Don't**: 활성 세그에 그림자·테두리 등 추가 장식.

### 24.3 라벨 규칙 — 합계 접미

톱 관례(`부가수익 (+16만)`, `보증금 (12만)`)를 **유지·정본화**한다. 탭 라벨에 요약 수치를 붙이면 전환 전에 규모를 가늠할 수 있어 유용.

| 항목 | 규칙 |
|---|---|
| 형식 | `{라벨} ({값})` — 라벨과 괄호 사이 space 1 |
| 단위 | 만 단위 축약 허용(`16만`) — **단, §07 금액 규칙의 "축약 금지 맥락"(정산·법적 금액)에는 붙이지 않음** |
| 부호 | 증감 의미일 때만 `+`/`−`(§07 부호 규칙 계승). 단순 합계는 무부호 |
| 폰트 | 괄호 안 수치는 **Pretendard tnum**(사선 없는 0). 별도 색 없음 — 라벨 색 상속 |
| 생략 | 값이 0이거나 계산 전이면 접미 생략(빈 괄호 금지) |

- **Do**: `지출 (−42만)` 처럼 부호+축약. **Don't**: `보증금 (1,240,000원)`식 항상(길어짐) / 빈 `자산 ()`.

### 24.4 개수 · 오버플로

| 상황 | 규칙 |
|---|---|
| 권장 개수 | **2~4개**. 5개→는 뷰 전환보다 필터/서브내비를 재검토 |
| 최대 | 5개 하드 리밋 |
| 모바일 넘침 | 컨테이너 `overflow-x:auto` + `scrollbar` 숨김 · 세그 `white-space:nowrap` · 좌우 페이드 마스크. **세그 축약(…)·줄바꿈 금지** |
| 활성 보장 | 스크롤 시 활성 세그가 뷰포트 밖이면 진입 시 `scrollLeft`로 활성만 보이게(스크롤만, `scrollIntoView` 금지) |

- **Do**: 4개 초과면 정보구조 재검토. **Don't**: 탭을 2줄로 wrap / 라벨을 `소모품→소모`로 자르기.

### 24.5 링크 탭 겸용 (라우트 이동)

재고 탭처럼 각 탭이 **별도 라우트**일 때도 **외형은 동일**. 요소만 `<a href>`.

- 마크업: `<a role="tab" href="…" aria-selected={isActive}>` — 외형 클래스는 버튼형과 동일.
- 활성 판정: 현재 경로와 매칭(`aria-selected`/`aria-current="page"` 병기 허용).
- 전환: 전체 새로고침 금지 — SPA `<Link>`(§23.4). `window.location.href` 금지.
- **Do**: 링크 탭도 코랄 채움 정본 외형. **Don't**: 링크라고 밑줄·파랑 등 앵커 기본 스타일 노출.

### 24.6 배치 · 반응형 · 접근성

**배치**
- 위치: 페이지 **제목 아래 한 줄**(제목 옆 금지 — 4개+ 라벨이 제목과 충돌). 본문 상단 여백 16px.
- MonthSelector 동시 존재: 같은 줄에 두면 **탭 좌측 / MonthSelector 우측** 정렬(`justify-between`). 모바일에선 탭이 위, MonthSelector가 아랫 줄.

**반응형·접근성**
- 모바일 터치 타겟 **44pt**: 세그 세로 padding을 `12px`로 올려 높이 44px 확보(데스크톱 40px).
- ARIA: 컨테이너 `role="tablist"` + `aria-label`, 세그 `role="tab"` + `aria-selected`, 대응 패널 `role="tabpanel"` + `aria-labelledby`.
- 키보드: `←/→`로 탭 이동, `Home/End`로 처음/끝, 활성만 `tabindex=0`(roving) — 나머지 `tabindex=-1`.
- `prefers-reduced-motion`: hover/활성 전환 트랜지션 제거.

### 24.7 Do / Don't

- **Do**: 뷰 전환은 어디서나 `ViewTabs`(코랄 채움) 하나로. 활성은 정확히 1개.
- **Do**: `role=tablist` + 키보드 roving + focus-visible 링 필수.
- **Do**: 라벨 합계 접미는 tnum·축약·부호 규칙(24.3)대로.
- **Don't**: 같은 "뷰 전환" 의미를 페이지마다 다른 컴포넌트로(§22.8 위반) — B·C 부활 금지.
- **Don't**: 필터(§22.2)에 같은 트랙 외형 사용 / '전체' 세그 추가.
- **Don't**: rounded-2xl·white 텍스트·그림자·2줄 wrap.

### 24.8 마이그레이션 표

| 현행 | 계열 | → 정본 변경점 |
|---|---|---|
| 재고 탭(소모품·부식/비품·자재) | A | 세맨틱만 추가(`role=tab`/키보드). 외형 유지 — **radius 12→10(r-md) 통일**, 링크 탭이면 24.5 |
| 수납 탭(수납/부가수익) | A | 위와 동일. 라벨 접미(`부가수익 (+16만)`) 24.3 형식 확인 |
| 재무 TABS(지출/자산/보증금/예비비) | **B → A** | 트랙형 폐기 → 코랄 채움. 4개라 `flex-1` 균등 또는 스크롤(24.4). role=tablist 유지 |
| 리포트 탭(결산/예상/AI 진단) | **C → A** | rounded-2xl 폐기 → r-md. `flex-1` 3등분 유지, white→cream, 코랄 채움 정본 |

### 부록 §24 — Tailwind 레시피 & `ViewTabs` API

**컨테이너**
```html
<div role="tablist" aria-label="뷰 전환"
  class="inline-flex rounded-[10px] border border-[var(--warm-border)] overflow-hidden bg-[var(--cream)] text-sm font-semibold">
  <!-- 세그들 -->
</div>
```

**활성 세그**
```
class="px-4 py-2.5 md:py-2.5 min-h-[44px] md:min-h-[40px] bg-[var(--coral)] text-[var(--cream)]
       focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-[var(--coral)]
       border-r border-[var(--warm-border)] last:border-r-0 transition-colors duration-150"
```

**비활성 세그**
```
class="px-4 py-2.5 min-h-[44px] md:min-h-[40px] bg-[var(--cream)] text-[var(--warm-mid)]
       hover:bg-[var(--cream-2)] hover:text-[var(--warm-dark)]
       focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-[var(--coral)]
       border-r border-[var(--warm-border)] last:border-r-0 transition-colors duration-150"
```

**균등 탭(3~4개)**: 컨테이너에 `flex w-full max-w-xl`, 각 세그에 `flex-1 justify-center`.
**모바일 스크롤**: 컨테이너에 `max-w-full overflow-x-auto [scrollbar-width:none] [&::-webkit-scrollbar]:hidden`, 세그에 `whitespace-nowrap shrink-0`.

**`ViewTabs` props (SegmentedControl과 겹치지 않는 API)**
```ts
// SegmentedControl = 필터(라디오, value 해제 가능). ViewTabs = 뷰 전환(항상 1개 활성).
interface ViewTab {
  id: string;              // 탭 식별자 (패널 aria-labelledby와 매칭)
  label: string;
  suffix?: string;         // 합계 접미: "+16만" | "12만" — 괄호는 컴포넌트가 붙임(24.3)
  href?: string;           // 지정 시 <a> 링크 탭(24.5). 없으면 <button>
  disabled?: boolean;
}

interface ViewTabsProps {
  tabs: ViewTab[];                          // 2~4 권장, 5 max
  activeId: string;                         // 항상 정확히 1개 — 필수(해제 없음)
  onChange?: (id: string) => void;          // button 모드에서만
  fill?: boolean;                           // true = flex-1 균등 탭
  ariaLabel: string;                        // role=tablist용
  // scroll·keyboard(roving)·focus 링은 컴포넌트 내부 기본 제공
}
```
- **API 차이 요약**: `SegmentedControl`은 `value: string | null`(해제=null, '전체'). `ViewTabs`는 `activeId: string`(null 불가). 접미(`suffix`)·`href`(링크 탭)는 ViewTabs 전용.

## §25 AI 지문 방지 — 마이크로카피·문장부호·모션 (Anti-AI-Tell)

> **계기**: 특정 AI로 만든 앱은 그 AI의 습관이 그대로 드러난다(운영자 지적 2026-07-06). 색·컴포넌트는 이 가이드가 정본이므로 유지하되, **문장부호·문구 톤·모션에서 "AI가 썼다" 티가 나는 패턴을 금지**한다. 목표: 어떤 도구로 만들었는지 화면만 봐서는 알 수 없는 상용 제품.

### 25.1 문장부호 (사용자 노출 문자열 전체)
- **em dash(" — ") 금지** — AI(특히 Claude) 최대 지문. 대체 규칙:
  - 뒤가 완결 문장이면 마침표로 두 문장: "저장됐습니다. 목록으로 이동합니다"
  - 짧은 부연이면 가운뎃점: "관리자 · 등록·수정·삭제 가능" (이 앱의 기존 · 관행과 일치)
  - 리스트 라벨의 설명이면 콜론: "아이폰: '캘린더에 추가'를 누르세요"
- **화살표(→) 최소화**: 이동 링크는 셰브론 `›`("전체 보기 ›"), 설정 경로 안내는 `>`("설정 > 캘린더").
  화살표는 **값의 전환 표시에만** 허용: "6월 → 7월로 변경", "보충 전 → 후", "퇴실→신규".
- **이모지 전면 금지**(기존 정책 재확인) — ⚠️·✅ 포함. 경고는 색·아이콘 토큰으로.
- **느낌표 금지**: 토스트·안내에서 "~했습니다!" 금지. 마침표로 끝낸다.

### 25.2 문구 톤
- 성공 토스트는 명사형 또는 간결한 완결문: "등록됨", "저장됐습니다". **"성공적으로 ~되었습니다" 금지**.
- 기능을 설명할 때 "~할 수 있습니다/해보세요" 반복 금지 — 동작 결과를 직접 서술.
- 버튼 라벨은 동사·명사 위주 2~6자 우선("추가", "영역 확정"). 문장형 버튼은 확인 칩 등 응답 선택지에만.

### 25.3 모션·장식
- `transition-all` 금지 — 필요한 속성만(`transition-colors`, `transition-[width]` 등).
- **데스크톱 hover 확대(hover:scale) 금지**. 터치 피드백 `active:scale-95~0.98`은 모바일 관행이라 허용.
- 그라데이션 배경·글로우 금지(현행 0건 유지). 그림자는 기존 토큰(shadow-lift 등)만.

### 25.4 적용 시점
- 새 UI 문자열·컴포넌트 작성 시 항상. loop.md 1번 UI/UX 정합 게이트의 "가이드 § 확인"에 이 §가 포함된다.
- 점검 명령: 사용자 노출 문자열에서 ` — `·`→`(전환 표기 외)·이모지·`요!` 검색이 0이어야 한다.
