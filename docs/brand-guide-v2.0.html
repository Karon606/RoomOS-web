§ 01 · 브랜드

브랜드

다크 리매핑 함정 · solid vs text 분리

-fg 토큰은 다크에서 밝은 값으로 뒤집힌다(#4E6834→#A3BF7B). 이 밝은 값을 흰/cream 글자 솔리드 배지 배경에 쓰면 대비가 붕괴한다. 그래서 -solid는 다크에서도 깊은 값으로 고정된다. 솔리드 배지/버튼 배경 = --{semantic}-solid + --on-solid 글자(#FBF6EF 양 모드 고정 · --cream 금지: 다크에서 표면색으로 뒤집힘, 2026-07-11 확정). 틴트 칩·인라인 텍스트·아이콘 = --{semantic}-fg + 투명 틴트 bg.

§ 27 · 문법

인터랙션 문법

색·컴포넌트가 통일돼도 "누르면 어떻게 되는가"가 화면마다 다르면 상용 제품이 아니다. 저장·실패·선택·되돌리기·취소·검색의 단일 정본이다. 신규 기능은 이 §를 통과해야 UI/UX 정합 게이트를 넘는다.

문법정본
27.1 저장 · 값의 무게로 결정단일 값 즉시 반영형(토글·스텝퍼·셀렉트 하나): 조작 즉시 저장 + 성공 토스트, 저장 버튼 없음. 폼형(입력 2필드 이상 또는 텍스트): 명시적 저장 버튼 상시 노출(조건부 등장 금지). 파괴적·대량 변경: 저장 전 ConfirmDialog + undo 병행. 같은 카드 안에서 두 문법 혼용 금지
27.2 실패 통지 · 채널은 원인이 정한다서버·통신 실패 = 토스트(전역 error). 화면 무반응 금지: 실패를 숨기면 사용자는 재클릭한다. 입력 검증 실패 = 인라인(필드 아래 붉은 캡션), 토스트 병행 금지. 같은 실패를 두 채널로 동시 통지 금지. fire-and-forget promise는 catch 필수
27.3 선택 모드 · 진입은 눈에 보이게다중 선택은 명시 '선택' 버튼(툴바)이 정본, 롱프레스는 보조 단축. 롱프레스 전용 진입 금지(발견 불가). 신규 페이지는 버튼부터 만든다
27.4 되돌리기 vs 확인창 · 위험도 비례비파괴 변경: 성공 토스트에 '적용취소' 액션(스냅샷 복원), 확인창 불필요. 파괴적 변경: ConfirmDialog(danger, impact 명시) 그리고 가능하면 undo도 제공. 확인창은 실수 방지, undo는 후회 구제: 역할이 달라 택일이 아니다. undo 불가능한 파괴 동작(외부 발송 등)은 확인창에서 고지
27.5 취소는 무해하다ConfirmDialog의 '취소'·Esc·배경 클릭은 항상 아무것도 바꾸지 않는다. 취소 버튼에 실 동작('영수증만 첨부' 등)을 싣지 않는다. 제3의 선택지가 필요하면 버튼을 3개로 (choiceDialog)
27.6 검색·필터 스코프검색은 현재 필터(탭·월) 스코프 안에서 동작. 스코프 밖 일치는 결과 하단에 "다른 보기에 N건 ›" 한 줄 안내 (자동 스코프 해제 금지). 월 셀렉터 범위 고지는 단일 문형: "OO은 선택한 달 기준입니다" 캡션 하나
✓ DO카드 단위로 저장 문법 하나를 고르고, 실패는 원인별 단일 채널로.
✕ DON'T조건부 저장 버튼 · 롱프레스 전용 선택 진입 · 취소에 실 동작 · 자동 스코프 해제.
