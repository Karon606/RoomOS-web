# 스테이음 전반 점검 계획 (2026-08, 운영자 오더)

세션이 토큰 한도로 끊겨도 이어갈 수 있게 **계획·진행·결정을 파일로 남긴다**.
새 세션은 이 파일 → `checklist.md`(진행 상태) → `context-notes.md`(결정 근거) 순으로 읽고 이어간다.

## 0. 이 점검의 전제

- **페이지별로 나누지 않는다.** 홈의 금액이 수납·지출·결산과 얽혀 있듯 화면은 축을 가로지른다.
  따라서 **유저가 하는 일(축) + 전문가 관점**으로 나눈다. (운영자 오더)
- **단서를 원인으로 단정하지 않는다.** 어떤 페이즈든 해당 축이 지나가는 **모든 화면을 전수로** 본다.
  (초기 조사에서 loading.tsx 보유 라우트 수 같은 지표가 나와도 그것은 가설일 뿐이다 — 운영자 지적)
- **loop.md 를 매 페이즈 시작·종료에 검토한다.** 특히 1번(필수 통과·UI/UX 정합·모바일 이원 검증),
  4번(스키마·인증·결제 로직·기획 충돌 = 운영자 승인), 5번(증거 보고).
- 각 페이즈는 **독립 완결**이다. 앞 페이즈가 안 끝나도 다음 페이즈를 시작할 수 있고,
  중간에 끊기면 체크리스트의 마지막 완료 항목부터 재개한다.

## 1. 상시 대동 전문가 (모든 페이즈)

운영자 지정 — 페이즈와 무관하게 항상 참여한다.

| 전문가 | 각 페이즈에서 보는 것 |
|---|---|
| UI/UX 전문가 | 사용자 흐름 끊김, 다음 행동 유도, 되돌리기 |
| 웹디자이너 | 정본 컴포넌트 재사용, 형제 화면 문법 일치, 가이드 § 준수 |
| 회계 전문가 | 금액·귀속·증빙의 회계적 타당성 |
| AI 전문가 | 회귀 위험 구조, 감지망 설계, 자동 검증 가능성 |
| 마케팅 — 홍보 | 대외 노출 문구·정보 정확성 |
| 마케팅 — 광고 | 유입 전환 경로, 랜딩 이탈 |
| 마케팅 — 브랜딩 | 톤·명칭·일관성(AI 티 금지 포함) |

해당 축과 접점이 없는 전문가는 **"해당 없음"으로 짧게 회신**해 토큰을 아낀다.

## 2. 모든 페이즈에 공통 적용하는 4대 점검축 (운영자 지정 최우선)

각 페이즈에서 그 축의 화면·액션 전부에 대해 아래를 기계적으로 확인한다.

1. **흐름 끊김** — 어떤 행동을 끝냈는데 다음으로 이어지지 않고 멈추는 지점.
   (저장했는데 화면이 안 변함, 목록으로 못 돌아옴, 종류·필터·월이 초기화됨 등)
2. **월 경계 파급** — 이번 달에 한 행동이 다음 달에 영향을 주는데 그 사실이 화면에 없는 것.
   (납부일 유예, 예약 전액 인식, 퇴실 일할, 락인, 선납, 인상 예약 등)
3. **스크롤·전환 먹통** — 스크롤 불가, 스켈레톤 순서 이상, 모달 갇힘. iOS/Android 이원.
4. **회귀** — 새 기능이 기존 기능을 죽인 흔적. 감지망이 없는 자리를 찾아 새로 건다.

## 3. 페이즈 구성 (유저 작업 축 기준)

### F. 화면 전환·반응성 [1순위]
운영자가 직접 지목한 문제. 다른 축과 독립적이라 먼저 끝낼 수 있다.
- 대상: **전 라우트 35개**(셸 안 21 + 셸 밖 14). loading.tsx 유무와 무관하게 전수.
- 보는 것: 페이지 전환 시 표시 순서(기존 화면 유지 → 딜레이 → 스켈레톤 → 목적지),
  스켈레톤이 간헐적으로만 나타나는 조건, 모달·시트 열림, 스크롤 먹통, 모바일 두 엔진 차이.
- 추가 전문가: 프론트엔드 성능(Next.js App Router 렌더·프리페치), 모바일 웹 스크롤

### A. 돈 [2순위]
수납 → 미납 → 지출 → 부가수익 → 결산 → 세무. 오류 시 금전 피해가 직접 발생.
- 대상 화면: rooms, dashboard, finance, report, card-settlement, accrual-check, stats, tenants(수납 모달)
- 보는 것: 같은 값이 두 곳에서 다르게 계산되는 자리, 월 귀속, 일할·할인·인상·락인,
  양도인 경계, 소프트삭제 반영, 현금영수증.
- 추가 전문가: 세무 전문가, 재무 데이터 정합 전문가

### B. 사람 [3순위]
문의 → 투어 → 예약 → 입실 → 거주 → 퇴실 → 환불. 흐름 끊김이 가장 많을 축.
- 대상 화면: tenants, requests, rooms, room-manage, dashboard(알림), contracts, floor-plan
- 보는 것: 상태 전이 누락·역행, 취소·되돌리기, 예약금·보증금 전환, 퇴실 정산 연결.
- 추가 전문가: 임대차 운영 전문가, 상태기계 설계 전문가

### E. 서류·알림 [4순위]
계약서 → 서명 → 확인서·영수증 → 발송 → 보관. 대외로 나가는 산출물이라 오류 비용이 크다.
- 대상 화면: contracts, contract/[tenantId], sign/[token], rent-receipts, rent-receipt/[tenantId],
  residence-certs, residence-cert/[tenantId], settings(도장·사업자)
- 보는 것: 문구 정확성, 금액 출처, 발행번호, 드라이브 보관·삭제복구, 전송 경로.
- 추가 전문가: 법무·계약 문서 전문가

### C. 물자 [5순위]
구매 → 수령 → 배치 → 점검 → 소진 → 발주. 재고는 이번 세션에도 사고가 났던 축.
- 대상 화면: inventory, inventory/assets, checklist, snap-upload, finance(지출 연결)
- 보는 것: 단위·배수, 허브 차감, 위치별 절대값, 무상 입수, 평균 소모율.
- 추가 전문가: 재고·물류 전문가

### D. 대외 [6순위]
공개 페이지 → 유입 → 방문분석 → 문의 전환. 마케팅 3인이 주도한다.
- 대상: public/members/*, marketing, market-analysis, api/track/*
- 보는 것: 다국어 4벌 일치, 팝업, 유입 경로, 전환 동선, 브랜드 톤.
- 추가 전문가: 번역 감수(EN/ZH/JA)

### G. 회귀 안전망 [상시 + 최종]
각 페이즈에서 발견한 클래스마다 감지망을 건다. 마지막에 전체를 묶어 한 번에 돌린다.
- 현재 감지망: test-money(99), test-due-date(33), verify-money-consistency,
  check-standalone-scroll, verify-recurring-estimate, check-restock-hub-drift,
  check-room-stay-drift, test-tour-feed
- 보는 것: 감지망이 없는 축, 커밋 전 자동 실행 여부, 새 페이지가 규칙을 우회하는 구멍.
- 추가 전문가: AI 전문가(주도), 테스트 아키텍트

## 4. 각 페이즈의 진행 방식 (5단계, 오류신고 규칙 준용)

1. **조사** — 읽기 전용. 코드·DB·실화면. 이 단계에서 수정 금지.
2. **전문가 패널** — 상시 7인 + 축 전문가. 서로 다른 관점이 나오면 이견을 그대로 보고한다.
3. **보고** — 무엇이 문제인지, 왜 생겼는지, 어떻게 고칠지, 순서. **운영자 승인 전 코딩 금지.**
4. **실행** — 승인된 계획대로만. 돌발 시 1로 복귀.
5. **증거 보고** — loop.md 5번. 검증 로그와 함께.

## 5. 진행 순서 요약

F(전환·반응성) → A(돈) → B(사람) → E(서류·알림) → C(물자) → D(대외) → G(안전망 최종)

G는 각 페이즈마다 조금씩 쌓고 마지막에 통합한다.
