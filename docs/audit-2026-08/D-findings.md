## 이 페이즈에서 확인된 클래스

**"권한만 남은 공개"** — 앱 화면이 쓰지도 않는데 Drive 공개 읽기가 붙어 무만료로 열려 있는 것.
E 페이즈의 서류 PDF 56건이 첫 사례였고, D 에서 세 자리를 더 찾았다.

| 자리 | 앱이 공개 URL 을 쓰나 | 처리 |
|---|---|---|
| 오류신고 첨부 16장 | **안 쓴다** (터미널 스크립트만) | 권한 회수 + 열람을 서비스 계정 다운로드로 이전 |
| 지출·대기 영수증 68개 | **쓴다** (화면 img) | 인증 프록시 신설 후 주소 이관 → 권한 회수 |
| 도장 1개 | **쓴다** (비로그인 서명 페이지·헤드리스 PDF 포함) | data URI 임베드 → 권한 회수 |

세 번째가 이 페이즈의 설계 판단이다. 도장은 **인증 프록시로 못 덮는다** — 쓰이는 세 곳 중 둘이
인증을 못 태운다(비로그인 `/sign/[token]`, 쿠키 없는 puppeteer). 바이트를 심으면 셋 다 덮이고
Drive ID 자체가 HTML 에서 사라진다.

**"저장하는데 읽지 않는다"** — `ctaClicks` 를 읽는 코드가 저장소 전체에 없었다. `activeMs` 는
저장해두고 화면은 스키마가 스스로 '레거시'라고 적어둔 `durationMs` 를 읽었다.
"같은 값을 두 곳에서 다른 규칙으로" 의 변종이다.

### 이견과 자체 철회

보안 담당이 `robots.txt` 경로 열거를 지적했다가 **스스로 철회**했다.
네 경로 전부 실제 인증으로 막혀 있고 레이아웃마다 `noindex` 가 있어 robots 의존이 아니다.
디자이너 판단도 같았다. 기록으로 남긴다 — 다음 세션이 같은 것을 다시 파지 않게.

### 확인 결과 이미 견고한 것

- **ID 추측으로 남의 서류가 열리지 않는다.** `contract/`·`rent-receipt/`·`residence-cert/[tenantId]`
  세 라우트 전부 `canReadScope('money')` + `propertyId` 일치 2단 게이트. 쿠키에 남의 UUID 를 실어도
  `propertyAccess` 가 매 요청 멤버십을 재검증한다.
- **서명 토큰은 잘 만들어져 있다.** `randomBytes(32)` · 24시간 TTL · 생년월일 2차 게이트 ·
  5회 실패 원자적 잠금 · httpOnly + HMAC 쿠키 이름 · 제출 후 무효화 · 사유 미구분 안내(열거 방지) ·
  서명 이미지 `data:image/(png|jpeg)` 만 허용(SVG 주입 차단).
- 갤러리 시트의 안드로이드 뒤로가기 대응과 Esc 계층 해제(라이트박스 → 360 → 시트)는 정확하다.
- 팝업은 닫기 경로 5개에 포커스 트랩·`prefers-reduced-motion` 가드까지 들어가 있다.
- 추적 엔드포인트의 입력 화이트리스트·상한 검증, geo 실패 폴백, KST 자정 분리, 키셋 페이징.

## 이 페이즈에서 건 감지망

새 파일 `scripts/check-public-site.mjs` (build 게이트에 물림) + `verify-money-consistency.mjs` 확장.

| 대상 | 무엇을 잡나 |
|---|---|
| 4벌 규칙 | `data-en` 가진 요소에 zh·ja 가 빠지면 |
| §29 | 노출 문구의 em dash·en dash·화살표·느낌표 |
| 공유 카드 | og 5종 중 하나라도 없으면 |
| CSS 충돌 | 미디어쿼리 밖에서 같은 단일 클래스 2회 정의 |
| 갤러리 다국어 | STR 사전이 4벌이 아니거나 **언어별 키 구성이 다르면** |
| 갤러리 접근성 | role/keydown/inert/Tab 트랩/포커스 복원/alt 중 하나라도 빠지면 |
| 추적 정합 | geo 가 create 앞으로 가면 · CTA 셀렉터 누락 · 팝업 이중 계상 · ctaClicks·activeMs 미사용 · 유령 섹션 선언 |
| 공개 권한 | 명단(로고·호실 사진) 밖에서 공개를 붙이거나 개수가 늘면 |
| 영수증 주소 | 저장된 주소에 `drive.google.com` 이 섞이면 (데이터) |
| 도장 | 공개 썸네일 URL 로 내보내는 파일이 있으면 |
| 캘린더 토큰 | `Math.random` 재사용 · 43자 미만 토큰 (데이터) |

**전부 결함 역주입으로 검출을 확인했다.** 그 과정에서 그물 넷이 처음에 못 잡아 고쳤다.

- CSS 충돌: 정규식으로 중첩 `@media` 를 못 갈라 규칙 절반을 놓쳤다 → 중괄호 깊이 추적
- `activeMs`: 부분 문자열이라 이름만 바꿔도 통과 → `r.activeMs ?? r.durationMs` 로 좁힘
- `open.kakao.com`: 같은 문자열이 주석에도 있어 셀렉터에서 빠져도 통과 → 셀렉터 선언 줄만 검사
- 포커스 복원: 같은 이유 → `lastFocus.focus()` 로 좁힘

**교훈** — 역주입을 안 했으면 넷 다 "통과하는 그물"로 남았을 것이다. 그물을 짜면 반드시 깨뜨려 본다.

## 설계 판단 기록

**공개 권한 감지망을 데이터가 아니라 명단으로 걸었다.**
"지금 공개인 파일이 있나"로 걸면 D6 이전 단계에서 영구 실패 게이트가 된다.
대신 **공개를 붙여도 되는 자리를 파일별 개수로 못 박고 명단 밖이면 위반**으로 잡는다.
명단에 넣으려면 "공개 URL 을 화면이 실제로 쓰는가"에 답할 수 있어야 한다.
D6 이후 명단에 남은 것은 로고와 호실 사진 둘뿐이다.

**영수증은 순서가 곧 설계다.** 프록시 신설 → 주소 이관 → 권한 회수.
반대로 하면 그 사이 화면이 죽는다. 서류(`/api/doc-file`)와 달리 화면이 공개 URL 을 실제로 쓰고 있었다.

**전이표(B페이즈)와 같은 원칙** — 쓰이는 것은 뜻이 성립하는 것이다.
표를 먼저 짜고 실측으로 검증했더니 실제 흐름 5종을 막고 있었다. 표를 넓혔다.
그물이 운영 흐름을 끊는 것도 결함이라 보고 "실제로 쓰인 전이를 표가 막으면 위반"을 그물에 넣었다.
