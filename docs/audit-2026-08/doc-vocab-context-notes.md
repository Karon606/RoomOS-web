# 서류 용어 정리 — 결정과 근거 (2026-08-01)

발단은 운영자 지적 두 개다. "납입영수증은 이미지로 송부가 가능한데 계약서는 그게 없네" 와
"비슷한 기능과 용어가 여러 군데 있어서 나도 헷갈려". 두 번째가 본질이다.
**매일 쓰는 사람이 못 외우는 화면은 그 자체로 결함이다.**

## 왜 갈렸나 — 원인 세 겹

1. **이름이 두 곳에서 정해진다.** `ShareDocButton` 의 기본 라벨이 '공유'인데 호출부가 `label` prop 으로
   덮어쓸 수 있다. 계약서 목록은 '보내기'로 덮었고 모달은 안 덮었다. 같은 컴포넌트, 같은 동작, 다른 이름.
   **근원 봉합 = 기본값을 정본으로 만들고 호출부 prop 을 전부 없애는 것.** 이름 정의처를 하나로 만들면
   다시 갈릴 수가 없다. 라벨만 맞추면 다음 호출부에서 또 갈린다.
2. **같은 클래스 동작에 서류별로 다른 동사.** 계약서만 '저장', 영수증·확인서는 '발급'.
   실제로는 셋 다 Drive 업로드 + 이력 기록으로 동일하다.
3. **한 동사가 서로 다른 동작 여럿을 가리킨다.** 보내기 3종(파일 전송 / 형식 선택 전송 / 서명 링크 문자),
   발급 2종(공식본 / 링크), 출력 2종(작성 화면 / 원본 열기, 둘 다 인쇄가 아님).

## 정본 동사 5개와 선정 기준

발급 · 보내기 · 저장 · 보기 · 작성.

기준은 "운영자가 처음 보고도 결과를 예측하는가" 하나다. 발급은 이력이 늘고, 보내기는 상대에게 가고,
저장은 내 기기에 남고, 보기는 흔적이 없고, 작성은 화면이 바뀐다. **다섯 결과가 서로 겹치지 않는다.**

'발급'을 정본으로 채택한 근거는 이미 앱에 확립된 의미가 있어서다. `knowledge/domain-contracts.md:34,39`
가 "계약서 저장(발급) = Drive 저장 + ContractFile 기록(공식 보관)"으로 못박고 있고, 화면에도
'발급 이력'·'2026.07.28 발급'이 일관되게 쓰인다. 새 말을 만들지 않고 있는 말을 정리하는 쪽이 맞다.

공유·시트·Drive·링크·세션 같은 개발·외부 서비스 용어는 라벨에서 뺀다(가이드 §29).

**예외 1건.** 스캔본 업로드는 앱 안으로 들어오는 유일한 방향이라 다섯 동사로 안 덮인다.
충돌 상대가 없어 혼동 위험이 없으므로 '스캔본 올리기' 한 라벨로 고정하고 사전 밖 예외로 둔다.

## 계약서 접점 8개 (지적은 6개였으나 전수 조사에서 2개 추가)

지적 6개에 더해 발견된 것.

- **#7 로컬 복제본.** `TenantClient.tsx:3811` 에 같은 이름의 `ContractFilesPanel` 이 따로 정의돼 있고
  수정 폼이 그걸 쓴다. 주석(`:3655`)은 "Prism 뷰어와 동일한 ContractFilesPanel"이라 적혀 있으나 사실이 아니다.
  복제본에는 계약서 보내기·서명 링크 배지·공유가 없다. **운영자가 "여기선 있는데 저기선 없네"를 겪는 주축.**
- **#8 파일명 링크 = #6 스캔본 출력.** 완전히 같은 동작인데 하나는 링크, 하나는 다이얼로그 뒤에 있다.

### #6 하단 '계약서 출력'을 제거하는 근거

코드로 확인한 결과 독자 기능이 0이다. 파일 0건이면 `/contract/[tenantId]` 를 열고(= #2와 동일),
1건 이상이면 다이얼로그 후 같은 URL 또는 `latest.viewUrl`(= #8과 동일)을 연다. 래퍼일 뿐이다.

게다가 **표기 버그를 만든다.** `files[0]` 은 `signedAt desc` 첫 건이라 `GENERATED`(시스템 발급본)일 수
있는데 다이얼로그는 무조건 "스캔본"이라고 쓴다(`EntityModal.tsx:231`). 보관 35건 중 11건이 발급본이라
스캔본을 한 번도 안 올린 입주자에게 "스캔본 출력"이 뜬다.

다만 하단 행은 스크롤 없이 닿는 자리라는 이점이 있었다. 그래서 **버튼을 지우는 대신 계약서 파일 섹션을
위로 올린다.** 하단 행에는 실거주 확인서·입실료 납부 확인서만 남아 "부속 서류"로 성격이 통일된다.

### #1 레거시 contractUrl

DB 실측 0건(LeaseTerm 89건 중 `contractUrl IS NOT NULL` 0건). 한 번도 그려진 적 없는 죽은 UI다.
**표시만 지우면 재유입된다** — 입력 필드(`TenantClient.tsx:3663`)와 저장 액션이 살아 있다.
운영자 결정은 화면 2곳(표시·입력) 제거, 컬럼과 액션은 유지. 컬럼 드롭은 별도 마이그레이션 판단이라 범위 밖.

### 섹션 이동 위치를 `TenantContractInfo` 다음으로 정한 이유

계약 정보(조건)와 계약서 파일(그 조건을 담은 서류)이 한 쌍이다. 그리고 서명 완료·발급 전 상태에서
홈 알림을 끄러 들어왔을 때 발급 버튼에 빨리 닿아야 한다. 밀려나는 것은 전부 조건부이거나 급하지 않다
(이사 이력은 방 옮긴 사람만, 환불 적용취소는 퇴실 건만, 단기 정보는 단기 고객만).
기본 정보·연락처 위로는 올리지 않는다. 이름·생년월일보다 서류가 먼저 나오면 순서가 뒤집힌다.

## 절대 건드리면 안 되는 것

**서명 링크 배지와 알림 해제 버튼.** `ContractFilesPanel.tsx:24-26` 이 기록한 503호 송호준 사고다.
서명 완료·링크 만료·발급 전 조합에서 알림을 끌 자리가 사라졌던 건. 정리한다고 상태별로 접으면 재발한다.
**규칙: `link` 가 있고 `closedAt` 이 null 인 동안 배지와 닫기는 상태와 무관하게 항상 렌더한다.**

**서명 받은 뒤의 주 동작은 반드시 '계약서 발급'.** 홈 알림 해소 조건은 `GENERATED` + 같은 `leaseTermId`
+ `createdAt >= link.signedAt` 뿐이다(`dashboard/alerts.ts:212-228`). 스캔본(`UPLOADED`)으로는 안 꺼진다.
스캔본 첨부를 나란히 두면 "첨부했는데 알림이 안 사라진다"는 다음 신고가 나온다.

**수정 폼에서 서명 요청을 숨기는 이유.** 복제본을 정본으로 통합하면 수정 폼에 서명 요청 버튼이 새로 생긴다.
링크 발급은 `templateSnapshot` 을 그 시점 DB 값으로 굳히므로(`schema.prisma:1431`), 호실·임대료를 고치는
중에 보내면 저장 전 옛 값으로 스냅샷이 나간다.

## 계약서 사진 송부 (4단계, 별건)

막혀 있던 이유는 `lib/pdfToPng.ts:16` 의 `doc.getPage(1)` 한 줄이다. 엔진(pdfjs) 제약이 아니다.
전송부 `shareFiles(files: File[])` 는 이미 배열을 받고 영수증 다건 전송에 쓰이고 있다.

**금지 주석이 괜한 게 아니었다.** 제기역점은 `disposalConsentTemplate.enabled = true` 라서 계약서가
실제로 2장이다. 검토 없이 영수증 버튼을 붙였으면 임의처분 동의서 장이 통째로 빠진 채 전송됐다.

방식은 페이지별 PNG 다건 공유. 세로로 이어붙이는 안은 배제한다 — 문자 앱 썸네일에서 못 읽고,
장수가 늘면 iOS 캔버스 면적 한계(2^24 px²)에 닿아 **예외 없이 빈 이미지가 조용히 만들어진다.**
계약서 페이지 수는 조항 분량·동의서 on/off·88% 축소맞춤 결과로 서버가 정하므로 상한에 기대는 설계는 금물.

무회귀 핵심. 기존 `pdfToPngBlob`(1페이지)은 시그니처·동작 그대로 두고 `pdfToPngBlobs` 를 신설한다.
`lib/docShareQueue.ts:63` 의 다건 큐 경로가 한 글자도 안 바뀐다. 파일명은 1장일 때 지금과 동일하게 두고
2장 이상일 때만 번호를 붙여, 영수증·실거주확인서는 첨부 개수·문구까지 현행과 동일해진다.

**정본은 Drive PDF, 사진은 전달 편의용.** 계약서는 법적 문서라 이 위치를 흐리면 안 된다.

## 인쇄 경로 (운영자 지적 2026-08-01, 1·2단계 배포 직후)

운영자 원문. "실제 프린터에서 출력하는 것은 여기서 안 되는 것 같은데. 보내기를 눌러야 하나?
계약서 메뉴로 별도 접속 안 하고는 방법이 없을까?"

**막힌 건 데스크톱뿐이다.** `ContractView.tsx:393-398` 에 이미 정본 결정이 적혀 있다.
모바일은 네이티브 공유 시트에 프린트가 들어 있고, 데스크톱은 새 탭에 PDF 를 열어 인쇄한다.
즉 휴대폰에서는 '보내기'가 곧 인쇄 경로인데 **이름이 보내기라 거기 있는 줄 모른다.**
데스크톱은 `shareOrDownloadFile` 이 다운로드로 떨어져 인쇄 경로가 아예 없다.

**기술적으로는 이미 절반이 깔려 있다.** `app/api/doc-file/route.ts` 는 `Content-Type: application/pdf`
로 스트리밍하고 `Content-Disposition` 을 붙이지 않아 브라우저가 인라인으로 렌더한다. 권한 검증도 있다.
`/api/doc-file?id=<driveFileId>` 를 새 탭으로 열면 브라우저 PDF 뷰어와 인쇄 버튼이 그대로 나온다.

**같이 드러난 반쪽 수정.** 1단계에서 'Drive 보기'를 '원본 보기'로 바꿨는데 목적지는 그대로
`https://drive.google.com/file/d/{id}/view` 다. 말만 정리하고 앱을 벗어나는 건 안 고친 셈이다.
`ContractFilesPanel` 의 파일명 링크도 같은 드라이브 URL 이다. 인쇄를 붙이는 김에 같이 앱 안으로 들인다.

## 남은 것

- 5단계 버튼 위계. 가이드 §22 "액션 행 주 버튼 1개만 solid --tc" 를 6개 액션 행이 전부 어기고 있다.
- 터치 타겟 드리프트. rent-receipts·residence-certs 행은 `min-h-[44px]` 인데 **contracts 만 `py-1.5`(약 30px)**.
  §10 은 44px 를 요구한다. 형제 3화면 중 하나만 어긋난 전형적 드리프트.
- 다건 선택 보내기는 PDF 고정으로 남긴다. png 로 바꾸려면 `DocShareQueue` 의 `blobs: Map<string, Blob>` 을
  배열로 넓혀야 해 영수증 다건 경로까지 건드린다. 운영자 지적은 단건 형식 선택지였다.
