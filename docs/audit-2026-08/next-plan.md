## 2군 — 수납 화면 표시 정합 (한 배포로 묶는다)

패널이 "뱃지만 먼저 내보내면 오히려 더 이상해진다"고 못박았다. 수납 화면에서는 405호가
유예로 순해지는데 홈 위젯에서는 그대로 미납으로 남기 때문이다. **2-1~2-3 은 한 커밋.**

### 2-1. 유예 표시 통합 (신고: 516호 이동찬)
405호와 516호를 같은 라벨 `납부 유예`(tone await)로. 보조 문구에 **대상월**을 넣어
밀린 정도를 구분한다(`7월분 8월 7일까지 · 5일 남음`).
- 어제 넣은 `unpaidBadgeLabel` 의 '납부 유예'는 **한쪽 분기 전용**이라 이번에 양쪽 공통으로 재배치
- 유예 판정 헬퍼를 두 분기 앞에 공통 배치. 조건은 "override 가 그 달에 걸림 + 원래 납부일보다
  뒤로 미룸 + 아직 안 지남 + 낼 게 남음"
- **미수 집계는 손대지 않는다.** 유예해준 돈이 화면에서 사라지면 안 된다
- 카드와 표는 쌍둥이라 반드시 같이
- 남는 불일치: 정렬 그룹·필터 칩은 여전히 갈린다(405 미납 / 516 납부예정).
  미납 칩 도움말에 "유예 중인 건도 포함됩니다" 한 줄로 관리

### 2-2. 홈 누적 미납 위젯에 유예 표식
`DashboardClient.tsx` `daysLabel`. 2-1 과 같이 안 나가면 화면 간 모순이 커진다.

### 2-3. 청구 없는 달 표시 (신고: 503호 송호준 "0원인데 완납")
뱃지 `청구 없음`(tone paid) + 보조 문구(`입주월에 전액 납부` / `8/6까지 납부됨`).
금액 자리는 `0원` 대신 `청구 없음` 텍스트. 총납부 옆에 `7/7 수납 470,000원` 캡션.
- 서버가 이유와 금액을 내려보낸다(`noBillReason`·`noBillCoveredAmount`)
- **`totalPaid` 숫자 자체는 안 바꾼다** — 월 격리 값이라 엑셀·AI 등 소비처가 그 의미에 의존
- 정렬·필터 무변경
- 상세는 `no-billing-display.md`

## 3군 — 수납 내역 (신고 2c6de978 잔여)

### 3-1. 수납 내역 3개월 표시
요청한 화면이 **이미 있다**(`PaymentHistoryAll`). full 모드 안 아코디언에 숨어 있어 못 본다.
- summary 로 승격 + 고객관리 쪽에도 같이
- 범위는 **조회월 기준 3개월**, 단 `payDate` 와 `targetMonth` **합집합**.
  과거 3개월만으로는 절반만 풀린다 — 이월은 미래로 가므로 7월 화면에서 8월 귀속분이 안 보인다
- 배지 기준을 "조회월과 다른가"에서 **"낸 달과 귀속월이 다른가"** 로. 안 바꾸면 3개월 창에서
  전부 켜져 소음이 된다
- 읽기 전용 유지(편집은 조회월 목록에만)
- `cashReceiptIssuedAt` select 추가 필요. **토글은 넣지 말 것**(이월 행에 스탬프가 붙으면 이중 계상)

### 3-2. "과납 이월" 문구
자동 문구가 사실과 반대로 읽힌다. 이 경로에서는 진짜 과납이 발생하지 않는다(남는 돈을 항상
다음 달로 민다). 쓰기 시점에 구분 가능하다.
- 앞 달이 완납이라 넘어옴 → `7월분 완납 후 넘어온 금액`
- 앞 달 잔액 채우고 남음 → `7월분 채우고 남은 금액`
- 단기 흡수(진짜 과납) → 기존 용어 유지
- 기존 메모 백필은 수납 데이터 쓰기라 **별도 승인**(loop.md 4번). 파싱하는 코드는 없음(확인)
