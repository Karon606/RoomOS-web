## 3. 운영자 확정 사항

- 보정 경계는 **점검 생성 시각** 기준으로 통일하고 과거는 소급 점검한다.
- 재고 화면 금액은 **전부 가린다**(서버에서 지운다).
- 품목 단위 자동채움은 **DB 에 쓰지 않는다**. 단위 변경 정본은 `changeTrackedItemUnit` 하나.
- 폐기 게이트는 **다음 날 이후 점검이 있을 때만** 막는다.

## 4. 남은 것

- **C-7** 지출 삭제가 재고에 반영되지 않는다. 그 구간이 음수가 되면 `avgDaily=null` 로
  **소진 알림이 조용히 사라진다**. 수령 후 지출의 수량·규격·품목명 수정도 자동 점검에 반영 안 됨.
- **C-8** `confirmAllPending` 이 자동 점검·배치·재고제외 필터·용량 게이트 없이 `receivedAt` 만 찍는다.
  UI 호출부는 없지만 서버 액션은 살아 있다. 삭제할지 재구현할지 결정 필요.
- **C-12** 지출 입력 폼의 `baseQtyOf` 가 단위를 모른다. 같은 구매가 지출 화면과 재고 화면에서
  다른 기준수량을 갖는다(라면 12,000 대 100).
- **C-13** 위치 강제 삭제가 `StockCheck.remainingQty` 헤더를 재계산하지 않아 지연 발화. 되돌리기 없음.
- **C-16~18** 재고 카테고리 축소·기본 창고 토글·무상 입수 회계 — 되돌리기 없음 또는 화면별 처리 상이.
- **적용취소 없음** — 전체 보정, 위치 간 이동, 위치 강제 삭제, 기본 창고 토글, 카테고리 변경.
- **점검 0회 12품목** — 첫 점검 유도 동선이 카드 안에만 있다.
