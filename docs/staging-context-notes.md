# 테스트 서버 — 결정과 그 근거

작업하면서 정한 것을 이어 적는다. 다음 세션이 같은 판단을 다시 하지 않도록.

## 판정을 긍정형으로 뒤집었다 (2026-08-03)

계획서는 `STAGING=1` 수동 플래그를 전제했다. 바꿨다.

`if (STAGING) 막기` 는 변수가 없으면 false 로 떨어지고, 그 기본값이 **실제 발송**이다. 환경변수 누락·스코프 오지정·오타가 전부 실발송으로 수렴한다. 그래서 `if (운영일 때만 보내기)` 로 뒤집고 근거를 `VERCEL_ENV === 'production'` 으로 잡았다. 이건 Vercel 이 직접 넣는 값이라 사람이 빠뜨릴 수 없다.

부작용으로 로컬 `next dev` 도 테스트로 잡힌다. 그게 맞다. 지금은 로컬에서 설정 화면의 테스트 푸시를 누르면 운영자 실기기로 진짜 알림이 간다. 로컬은 운영이 아니다.

실패 모드는 하나 남는다. preview 배포를 운영으로 승격하면 `VERCEL_ENV` 가 빌드 시점 값이라 preview 로 굳어 푸시가 안 나간다. 방향이 안전한 쪽이고(안 나감이 잘못 나감보다 낫다), `NEXT_PUBLIC_*` 인라이닝도 같은 성질이라 승격 금지는 어차피 지켜야 한다.

## 배너와 발송 차단은 같은 함수에서 나온다

갈라두면 최악의 조합이 생긴다. **배너는 없는데 발송은 막힌 상태.** 운영자가 실제 사이트라고 믿고 문자를 보냈다고 생각하는데 아무것도 안 나간다. 그래서 `lib/env.ts` 의 `isLiveEnv()` 하나에서 둘 다 파생시키고, 감지망이 이 정본 밖에서 환경변수를 직접 읽는 걸 잡는다.

## 배너는 fixed 인데 높이는 예약한다

셸 안에 flow 요소로 넣으면 `(app)` 밖 라우트(로그인·서명·서류)가 전부 빈다. 그렇다고 root layout 에 flow 로 넣으면 `html, body { overflow: hidden; height: 100% }` 잠금 때문에 하단이 잘린다.

그래서 root layout 에 fixed 로 두고, 높이만 `--sysbar-h` 로 예약해 셸이 그만큼 줄어들게 했다. **운영에서는 `--sysbar-h` 가 `0px` 이라 모든 calc 이 종전 값과 같다.** 배너 자체도 서버에서 조건부로 렌더 안 한다. 운영 렌더링에 변화가 없다.

`--shell-content-h`(globals.css)도 같이 뺐다. 그 주석이 이미 경고하고 있다 — 셸 크롬을 추가하면 여기 합산하지 않으면 도면 편집기 하단이 잘린다.

fixed 로 둔 대가로 `(app)` 밖 페이지에서는 배너가 상단 26px 를 덮는다. 그 페이지들은 세로 가운데 정렬이라 가리는 게 없다. 셸과 admin 만 높이를 예약했다.

## 색은 의미색을 안 썼다

`--pill-bg` + `--on-solid`. 경고색(앰버)을 쓰면 안 되는 이유는 그게 미납 전용이기 때문이다. 화면 최상단에 앰버가 **항상** 떠 있으면 앰버 자체가 배경 소음이 되고 미납 배지가 죽는다. `--pill-bg` 는 의미색이 아니라 크롬 색이고 다크에서 뒤집히지 않는 것이 이미 검증돼 있다(`--ink` 를 썼으면 다크에서 밝아져 크림 글자와 겹쳐 사라진다).

관리자 뷰 배너가 같은 색을 쓴다. 둘이 동시에 뜨면 검정 띠 두 줄이 쌓이는데, 색을 바꾸는 게 아니라 나중에 하나의 띠 슬롯으로 합치는 게 맞다.

## aria-live 를 붙이지 않았다

이 띠는 상태 변화가 아니라 변하지 않는 환경 사실이다. `role="status"` 나 `aria-live` 를 달면 라우트 전환으로 리마운트될 때마다 스크린리더가 같은 문장을 다시 읽는다. 하루 수십 번이다. `role="region"` + `aria-label` 로 랜드마크만 만들어 로터에서 찾아갈 수 있게 했다.

## 초크포인트가 하나가 아니었다

계획서는 `lib/pushSend.ts` 만 막으면 된다고 봤는데, `settings/pushActions.ts` 의 `sendTestPush` 가 `web-push` 를 직접 부르고 있었다. 자체 VAPID 설정과 자체 410/404 정리까지 복제돼 있었다. 가드를 두 곳에 붙이는 대신 `sendToSubscriptions` 로 접었다. 문이 둘이면 셋째가 생겼을 때 또 뚫린다.

## 문자는 서버 발송이 아니다

`sms:` URL 로 운영자 폰의 메시지앱을 여는 방식이라 서버가 자동으로 보내는 경로가 없다. 계획서 4번의 무게는 전부 푸시 쪽에 실려 있다. 문자 쪽은 버튼을 잠그는 문제이고, 조립 지점이 4곳인데 정본 헬퍼(`lib/smsHref.ts`)를 쓰는 건 1곳뿐이라 먼저 수렴시켜야 한다.

## Drive 는 계정을 나눈다 (운영자 결정)

폴더 분리가 격리가 아니라서다. `GOOGLE_DRIVE_FOLDER_ID` 는 업로드의 `parents` 에만 쓰이고, 삭제·휴지통·공개권한 부여·다운로드는 전부 fileId 만 본다. `isOwnedByApp` 도 `ownedByMe` 만 보므로 같은 계정이면 운영 파일이 그대로 통과한다. 복사한 DB 의 `driveFileId` 가 운영 실파일을 가리키니, 스테이징에서 입주자를 지우면 운영 계약서가 휴지통으로 간다.

계정을 나누면 코드 변경 0 으로 이 전부가 닫힌다. 폴더 소속 검증을 코드로 넣는 안은 운영 경로를 건드리는 데다 검증 왕복이 한 번 더 붙어서 뒤로 미뤘다.

## 복사 데이터는 토큰·구독만 지운다 (운영자 결정)

이름·연락처·생년월일·서명을 남기는 이유는 이 프로젝트 버그의 대부분이 실데이터 형상에서만 재현되기 때문이다. 일할 경계, 청구 락인, RESERVED 혼입, 규격 단위. 이름과 전화번호가 그 버그를 만들지 않는다. 그리고 `Tenant.birthdate` 는 `/sign` 게이트의 자격이라 바꾸면 원격 서명을 끝까지 못 돌린다.

대신 마스킹하지 않는 대가로 비밀번호 잠금과 계정 분리가 조건이 된다. 그 둘이 안 되면 이 결정은 성립하지 않는다.

명단형 방어라는 약점은 남는다. 나중에 토큰 컬럼이 추가되면 무효화 명단에서 빠질 수 있다. 서류 3종만 훑어서 신고 첨부 16건을 놓친 회수 스크립트와 같은 실패 유형이다. 그래서 무효화 확인을 체크리스트에 넣었다.

## Vercel 환경변수를 Sensitive 로 저장하면 안 된다 (2026-08-03 실측)

DB 비밀번호를 회전하고 Vercel `DATABASE_URL`·`DIRECT_URL` 을 갱신했는데, 재배포를 세 번 해도
운영이 계속 `P1000 Authentication failed` 를 뱉었다. 코드도 배포 상태도 정상이라 원인을
env 스코프·따옴표·중복 항목 쪽에서 찾고 있었는데, 실제 원인은 **Sensitive 옵션**이었다.
끄자마자 정상화됐다.

이 실패가 고약한 이유는 신호가 없다는 것이다. 배포는 READY 로 뜨고, 런타임 오류는 인증 실패
하나뿐이라 "값이 안 넘어갔다"와 "값이 틀렸다"를 구분할 수 없다. 그리고 Sensitive 로 저장된
변수는 대시보드에서 값을 볼 수 없어서 눈으로 대조하는 것도 안 된다.

테스트 서버 착수 때 Preview 스코프에 환경변수를 여럿 새로 넣어야 하는데, 거기서 같은 실수를
하면 증상이 "테스트 사이트가 안 뜬다"로만 보인다. 체크리스트 2단계에 못 박아뒀다.
