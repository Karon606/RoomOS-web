# Claude Design 의뢰 프롬프트 — v1.3.1 추보: 콜드 스타트(최초 접속) 로딩 체계

> 아래 전체를 Claude Design에게 그대로 전달. 결과물은 brand-guide-v1.3 에 §18로 추가될 추보(addendum).

---

당신은 stayeum(스테이음) 브랜드 디자이너입니다. v1.2·v1.3 가이드에 이어,
**최초 접속(콜드 스타트) 로딩 체계**를 §18로 추보해주세요.

## 왜 필요한가 — 현재 가이드의 충돌·공백

기존 규정:
- v1.2 §08 브랜드 로더: 아치 line-draw 3.2s 사이클, ×2 사이클마다 워드마크 EN(stayeum)→KO(스테이음) 교차. 용도는 **"페이지 이동·라우트 전환"**.
- v1.3 §16: 첫 로딩=**스켈레톤**, 갱신 중=상단 진행 바 2px, 라우트 전환=브랜드 로더(--z-loader 500). "스켈레톤과 진행 바 동시 사용 금지".

실제 구현(stayeum.com)과 대조하면:

1. **[충돌] '최초 접속 스플래시'가 무규정.** 현재 코드는 도메인 첫 진입 시 풀스크린
   스플래시(배경 `--canvas`/페이지 톤 + 브랜드 로더 lg)를 띄우는데, v1.3 §16대로면
   첫 로딩은 스켈레톤이어야 해서 이 스플래시는 근거 없는 존재가 됨. 그러나 앱 셸이
   아직 없는 콜드 부트(로그인 전, 인증 확인 중)에는 스켈레톤을 그릴 레이아웃 자체가
   없어 §16을 적용할 수 없음 — 이 구간의 규정이 필요.
2. **[충돌] 라우트 전환 시 이중 표시.** 현재 페이지 간 이동에서 ① 본문 스켈레톤
   (셸 유지)과 ② 브랜드 로더 오버레이(본문 영역 덮음)가 동시에 발동. v1.2 §08과
   v1.3 §16이 같은 상황에 다른 답을 줘서 생긴 충돌 — 우선순위 판정 필요.
3. **[공백] 첫 페인트 전 흰 화면(FOUC).** HTML 도착 전 브라우저 기본 흰 화면.
   브랜드 배경을 가장 먼저 보이게 하는 규정(html 배경색, 다크모드 포함) 없음.
4. **[공백] 로더 최소 노출/표시 지연.** 빠른 전환(<300ms)에서 3.2s 모션이 잘려
   깜빡임(flash)으로 보임. "N ms 이상 걸릴 때만 표시, 표시했으면 최소 M ms 유지"
   임계가 없음.
5. **[공백] 로그인 화면 자체의 로딩 상태** (제출 중·소셜 인증 리디렉트 대기).
6. **[공백] PWA OS 스플래시와의 연속성.** 현재 manifest: background `#E8DDD0`
   (page), theme `#A03C2E`(tc). OS 스플래시(아이콘+배경) → 웹 스플래시 → 앱 셸로
   이어지는 3단계의 시각 연속성 규정 없음.

## §18에서 규정해 줄 것

### A. 로딩 상황 결정표 (최우선)
"어떤 상황엔 무엇 하나만"을 한 표로. 최소한 이 6가지 상황 각각에 패턴 1개 배정:
① 도메인 콜드 부트(셸 없음, 인증 확인 중) ② 로그인 → 앱 첫 진입(셸 생성)
③ 앱 내 라우트 전환(셸 유지) ④ 같은 페이지 데이터 갱신 ⑤ 모달/위젯 내부 로딩
⑥ PWA 실행. 현재 충돌(②·③에서 스켈레톤 vs 브랜드 로더)의 명확한 판정 포함.

### B. 콜드 스타트 스플래시 스펙
- 배경색(현재 `--canvas` 페이지 톤 vs `--cream` vs 브랜드 컬러 풀블리드 중 결정),
  다크모드 값, 로더 크기/위치, 워드마크 노출 여부(첫인상 vs 로딩 속도감 트레이드오프).
- 사라질 때 전환(fade-out 시간·이징, 앱 셸과 크로스페이드 여부).
- 최대 허용 시간 가이드(예: 5초 초과 시 "연결이 느립니다" 메시지 추가?).

### C. 타이밍 임계 토큰
```
--loader-delay:    ___ms   (이보다 빨리 끝나면 로더 아예 안 보임)
--loader-min:      ___ms   (한번 보였으면 최소 유지 — 깜빡임 방지)
--splash-fade:     ___ms   (스플래시 → 콘텐츠 전환)
```
브랜드 로더 3.2s 사이클과의 관계(중간 잘림 허용? 사이클 정수배 대기?)도 결정.

### D. FOUC 방어
첫 페인트 전 배경 규정 — html/body 기본 배경색(라이트·다크), 시스템 다크모드
감지 전 깜빡임 방지 방침.

### E. 로그인 화면 로딩
제출 버튼 진행 상태, 인증 리디렉트 대기 중 표시(스플래시 재사용? 버튼 스피너?).

### F. PWA 연속성
OS 스플래시(manifest 배경·아이콘) → 웹 스플래시 → 셸의 3단계 색·로고 연속성 규칙.
manifest background/theme 값이 v1.2 토큰과 일치하는지 점검 기준.

## 결과물 형식
- 마크다운, §18 단일 섹션 (v1.3 문서에 그대로 이어붙일 수 있게).
- 신규 토큰은 CSS 변수+값. 결정표는 표로. 각 항목 Do/Don't 1줄.
- 임의 결정엔 근거 1줄. "적절히" 같은 모호어 금지.

## 참고 — 현재 구현 요약 (코드 사실)
- `/` 접속 → 서버 즉시 `/login` 리디렉트. 루트 로딩 폴백 = 풀스크린 스플래시
  (`--canvas` 배경 + 브랜드 로더 lg, z 500).
- 앱 내 전환 = 본문 스켈레톤(셸 유지) + 브랜드 로더 오버레이(본문 덮음) **동시 발동**.
- 갱신 = 상단 진행 바 2px (v1.3 §16 그대로, 정상).
- PWA manifest: background #E8DDD0 / theme #A03C2E / 아이콘 보유.
