# Claude Design 의뢰 프롬프트 — stayeum 브랜드가이드 v1.3 (인터랙션 확장판)

> 아래 전체를 Claude Design에게 그대로 전달. 결과물(v1.3 가이드)을 받으면
> 개발 측(Claude Code)이 코드에 일괄 반영할 예정.

---

당신은 한국 임대관리 SaaS **stayeum(스테이음)**의 브랜드 디자이너입니다.
기존 브랜드가이드 v1.2를 **인터랙션·컴포넌트 영역으로 확장한 v1.3**을 작성해주세요.

## 배경

stayeum은 고시원·원룸 운영자가 쓰는 따뜻한 톤(Terracotta·Cream·Ink)의 관리 앱입니다.
v1.2는 색·상태 5단계·모달·토스트·radius·폰트·모션을 규정했지만, 실제 앱을 전수 감사한 결과
**가이드에 없는 인터랙션 패턴들이 화면마다 제각각으로 구현**되어 있었습니다.
v1.3의 목표는 이 공백을 메우는 것입니다. 개발자가 기계적으로 적용할 수 있도록
**모든 스펙은 CSS 변수/수치/상태별 값으로** 적어주세요.

## 기존 v1.2 핵심 토큰 (유지 — 변경 금지, 참조용)

- 색: `--tc #A03C2E`(Terracotta, Primary/CTA/OVERDUE) · `--tc-d #7C2D26` · `--camel #C8A07D` · `--sand #F2D9B8` · `--cream #FBF6EF`(카드/모달, #fff 금지) · `--ink #3D2418`(#000 금지) · `--ink-s #7A6553` · `--ink-m #A89380` · `--success #4E6834`(Warm Olive) · `--page #E8DDD0` · `--border rgba(61,36,24,.10)`
- 상태 5단계: PAID(올리브) / AWAIT(블루 #1e40af) / UNPAID(앰버 #8B5E0A) / **OVERDUE(테라코타, 7일+, 좌측 3px 팁)** / VACANT(뮤트)
- radius: r-xs 4 / r-sm 6(입력·배지) / r-md 8 / r-lg 10 / r-xl 14(카드) / r-2xl 18(모달) / r-pill
- 폰트: Pretendard Variable(UI) · DM Mono(금액·KPI, tnum) · Plus Jakarta Sans(워드마크 전용)
- 모션: --dur-fast 100ms / --dur-base 150ms / --dur-slow 200ms · 모달은 cubic-bezier(.4,0,.2,1)
- 모달: backdrop black/70, r-2xl, ESC·backdrop 닫기, z 200+
- 토스트: ink 배경 + success/warn/error/urgent 4종 (규정상)
- 접근성: 터치 타겟 44px, focus-visible 링 필수, prefers-reduced-motion 대응

## 감사로 확인된 현재 실태 (v1.3이 해결해야 할 문제)

1. **네이티브 confirm()/alert() 71곳** — 삭제·전환·기록 등 모든 확인이 브라우저 기본 다이얼로그.
   특히 "파괴적 삭제 2차 동의" 플로우(아래 4번)도 confirm 2연타로 처리 중.
2. **수제 모달 17개 파일** — 공용 Modal 컴포넌트 대신 직접 구현. Esc 지원·세이프에어리어·
   최대 높이·radius가 파일마다 다름.
3. **입력 radius 혼용** — rounded 6px(176곳)·14px(132곳)·10px(19곳)·8px(10곳)이 같은 폼 안에도 혼재.
4. **토큰 밖 색상** — 27개 파일이 raw 팔레트(red·emerald·blue·purple) 사용. 대시보드는
   자체 hex 12종(#a855f7 보라, #3b82f6 블루, #10b981 그린, #6366f1 인디고 등)으로 KPI·차트·
   상태색을 칠하고 있어 상태 5단계와 어긋남. 연체(OVERDUE) 단계가 대시보드에는 아예 없음.
5. **토스트** — 코드는 success/error/**info** 3종(가이드의 warn·urgent 미구현, info는 미규정).
   위치는 화면 정중앙 고정, 2400ms 고정. 최근 "결과+부가 설명"형 안내(예: "퇴실일 변경으로
   일할 정산을 재계산했습니다 — 19일치 253,333원")가 늘어 긴 메시지 패턴이 필요.
6. **z-index 10종 난립** — 10/20/30/40/50/[60]/[200]/[210]/[300]/[400]. 헤더·드롭다운·모달·
   중첩 모달·라이트박스·토스트의 층 위계가 미규정.
7. **버튼** — 공용 Btn(variant 5종: primary/secondary/danger/ghost/subtle) 143곳 vs
   raw button 439곳. raw는 포커스 링·44px 타겟 누락 다수.
8. **금액 표기** — 유틸 포맷(7곳) vs 인라인 `toLocaleString()+'원'`(수백 곳) 혼재.
   음수(환불·감액)·0원·만원 단위 축약(예: 43만)의 표기 규칙 없음.

## v1.3에서 새로 규정해 줄 패턴 (우선순위순)

### A. 확인 다이얼로그 (Confirm Dialog) — 최우선
네이티브 confirm을 대체할 브랜드 다이얼로그 스펙.
- 3단계 위험도: ① 일반 확인(기록/전환) ② 주의(되돌리기 가능한 변경) ③ **파괴적(영구 삭제)**
- 파괴적 단계는 **영향 범위 고지형**: "과거 계약 3건·수납 기록 24건이 함께 영구 삭제됩니다"처럼
  건수·결과를 보여주고 동의받는 레이아웃 (제목/영향 목록/경고문/버튼 배치·색).
- 버튼 순서(취소-확인 좌우), 파괴 버튼 색(--tc 사용 여부), Esc/배경클릭 허용 여부 각 단계별로.
- 선택지가 3개 이상인 경우(예: "스캔본 출력 / 시스템 계약서 출력 / 취소")의 액션 시트형 변형.

### B. 적용취소(Undo) 노출 패턴
이 제품의 확고한 원칙: **"적용하는 모든 기능엔 적용취소가 항상 있어야 한다."**
현재 undo가 위젯 안 '해제' 버튼, 모달 안 '병합 해제', 상세의 '다시 포함' 버튼 등 제각각.
- undo 진입점의 표준(위치·라벨 규칙·아이콘·색 — 예: '적용취소'/'해제'/'되돌리기' 용어 통일)
- 토스트에 [실행취소] 액션을 넣는 패턴 도입 여부와 그 스펙(지속 시간, 액션 버튼 스타일)
- "되돌릴 수 없는 동작"의 시각적 구분(라벨·아이콘) 규칙.

### C. 토스트 체계 재정의
- kinds 확정: success / error / info(안내) (+ 가이드의 warn·urgent 유지 여부 결정)
- info(부가 설명형, 2~3줄 장문)의 스타일·최대 폭·지속시간(장문은 더 길게? 수동 닫기?)
- 위치(현 화면 정중앙 vs 하단/상단), 다중 토스트 스택 규칙, 액션 버튼(B의 실행취소) 수용.

### D. 레이어(z-index) 위계표
헤더 / 사이드바 / 드롭다운(알림벨·셀렉트) / 일반 모달 / 모달 위 모달(2~3중) /
액션시트·확인 다이얼로그 / 라이트박스·360뷰어 / 토스트 / 브랜드 로더 — 전 층의 토큰화
(예: --z-header 100, --z-dropdown 150, …). 중첩 모달에서 Esc는 최상단만 닫는 규칙은 이미
코드에 구현됨 — 가이드에 명문화만.

### E. 폼 입력 표준
- 입력·셀렉트·날짜·금액 입력의 radius 단일화(기존 r-sm 6px 유지? 현 다수파는 6px) +
  높이·패딩·포커스 보더 색·placeholder 색을 한 표로.
- 모달 안 폼 작성 중 배경클릭으로 닫혀 입력이 유실되는 문제 → "입력 시작 후엔 배경클릭 무시"
  또는 "닫기 전 확인" 중 정책 결정.
- 자동 합산 필드(읽기전용 강조 표시), 상호배타 체크박스 그룹(배송비 2모드 같은), 임시저장
  상태 표시의 시각 규칙.

### F. 상태·색상 확장
- 대시보드 KPI·차트·분포 그래프용 **확장 팔레트**: 상태 5단계와 충돌하지 않는 데이터 시각화
  색 6~8종을 브랜드 톤(웜 계열)으로 새로 정의 — 현재의 보라/블루/그린 hex 대체.
- 상태 5단계의 적용 범위 명시: 수납 표·호실 카드·대시보드 방현황·알림 행 전부 동일 토큰 사용.
- [미납][퇴실 예정]처럼 **뱃지 2개 병렬** 패턴의 간격·순서·보조줄(예: "12일 초과 · 6/13 퇴실 D-3") 규격.

### G. 금액·숫자 표기 규칙
- 원화 표기(쉼표·'원' 접미), 음수(환불 −80,000원? 빨강?), 0원, 큰 금액 축약(1,234만) 사용처,
  DM Mono+tnum 적용 범위(표·KPI는 필수 등).
- 증감 표시(+2만 선납 / −5만 미수)의 색·부호 규칙 — 양수=초록 계열? 웜 올리브?

### H. 빈/로딩/스켈레톤 상태
- 첫 로딩(스켈레톤) vs 갱신 중(상단 진행 바, 이미 구현) vs 빈 상태(EmptyState)의 사용 구분과
  각 스펙. '불러오는 중…' 인라인 텍스트의 허용 여부.

### I. 반응형 전환 규칙
- 모바일 카드 ↔ 데스크톱 표 전환 브레이크포인트와, 카드에서의 정보 우선순위(어떤 열을
  카드 1행/2행/뱃지로 보낼지) 일반 원칙.

## 결과물 형식 (중요)

- 마크다운 단일 문서 "brand-guide-v1.3.md" — v1.2의 기존 섹션은 반복하지 말고
  **추가/변경분만** (v1.2 호환성 메모 방식 유지).
- 모든 신규 토큰은 CSS 변수명 + 값으로 (예: `--z-modal: 200`, `--toast-info-bg: …`).
- 각 패턴은 ①스펙(수치) ②사용 규칙(언제 무엇을) ③Do/Don't 1줄씩.
- 개발자가 그대로 구현할 수 있게 애매한 표현("적절히", "조화롭게") 금지.
- 결정이 필요한 곳은 임의로 정하되 근거 1줄 (우리가 재검토 가능하게).
