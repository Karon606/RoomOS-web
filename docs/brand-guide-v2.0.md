## §01 브랜드

- 미션: "머무름과 이음이 만나는 곳에서, 운영자가 더 여유롭게 사람을 만날 수 있도록."
- 3가지 이음: 1 운영자와 입실자를 잇다(관계) · 2 데이터와 의사결정을 잇다(직관) · 3 과거의 기록과 미래를 잇다.
- 성격: 따뜻하고 인간적 · 묵직하고 신뢰감 · 차분하고 안정적 · 현대적이고 깔끔. 아닌 것: 통통 튀는, 차갑고 기술적, 부동산 앱(직방·다방), 호텔·여행 앱(Airbnb) 느낌.
- 보이스: 명확·사실적·짧고 구체적("401호 입실자 수납 완료"), 조용한 피드백("저장되었습니다"). 과도한 캐주얼·이모지·격려 문구·과잉 긍정 금지. 상세는 §29.
- 표기: 본문 stayeum / 스테이음. 워드마크 stay**eum** / 스테이**음** (eum·음만 테라코타). 금지: StayEum, STAYEUM, stay-eum, stay·eum. 도메인 stayeum.com.

- 보조 잉크 하한(2026-10-23 운영자 승인, 2026-10-26 시공): 라이트 보조 잉크는 라이트 불투명 면(--canvas·--cream·--cream-soft·--cream-3) 전부에서 4.5:1 이상이고, 본문 --ink-2 와 2.0:1 이상 떨어져 위계가 남는다. 종전 #7A6553 은 --canvas 위 4.11:1(배지·캡션 17곳, 배치도 회색 버튼, 월 선택 '이번달')이라 자리마다 고치지 않고 값을 내렸다. 헤드리스 Chrome 계산된 색 실측 라이트 --canvas 4.11 에서 5.18, --cream 5.12 에서 6.45, --cream-3 3.59 에서 4.52. 다크는 --d-ink-s 그대로이고, --d-ink-m 만 보조 표면 --d-card-2 위 4.46:1 로 미달이라 #93816F 에서 #948270 으로 한 단 밝혔다(4.52:1, §28). 감지망 `scripts/check-seg-ink-off.mjs` ⓖ.

- 상태 5단계 (좌측 팁 = fg와 동일):

- 적용 범위 전면 통일: 수납 표·호실 카드·대시보드 방현황·알림 행·필터 칩. 대시보드에도 OVERDUE 필수. 상태색을 차트에 쓸 땐 상태 토큰 그대로 (viz 대체 금지).
- 예외 — 카드 베이스는 상태 틴트와 다른 축이다: 표의 bg 는 배지·칩·행 틴트용이고, 카드·타일이 통째로 깔고 앉는 표면은 --card-resident-bg(거주 중) · --card-vacant-bg(비거주·공실) · --card-neutral-bg(일반) 세 종을 쓴다. VACANT 행의 --neutral-bg 를 타일 표면에 끌어다 쓰지 않는다 (홈 방 현황 무색 밴드 = --card-vacant-bg, 2026-08-12 명문화).
- **밴드 표면 5종 (--band-*, 2026-08-12 신설)** — 카드 베이스와 같은 축이고 상태만 5단계로 늘린 티어다. 홈 방 현황·비거주자 현황 타일과 **입퇴실 캘린더 간트 막대**(2026-08-20 등재). 판정 기준은 하나다 — 표면 **하나가** 상태를 혼자 말하는 자리인가. 배지·행 틴트는 옆에 선 fg 글자가 뜻을 지므로 이 티어를 쓰지 않는다. 위 표의 bg 는 옆에 선 fg 글자가 뜻을 지고 틴트는 거들기만 하는 자리라 알파가 낮은데, 46타일 격자는 표면 하나가 상태를 혼자 말한다. 그 티어를 그대로 끌어 쓴 결과 라이트 최소 ΔE76 이 3.23(완납 대 공실)까지 붙어 "라이트건 다크건 구분이 안 된다"는 신고가 들어왔다. hue 는 위 표·§04 정본 그대로 두고 알파 단계만 올린다 — 임의 hex 금지는 여기서도 그대로다.

- 밴드 티어 판정 기준(이 값을 고칠 때 다시 재는 것): 다섯 표면의 열 쌍 전부 ΔE76 ≥ 12, 그중 완납-예정·완납-공실·예정-공실·미납-연체 네 쌍은 ≥ 15. ΔE76 2.3 이 이상적 인접 비교의 1 JND 이고, 6px 간격으로 흩어진 작은 타일을 곁눈으로 대조하는 조건이라 5배(≈12)를 바닥으로 잡았다. 색각 1·2·3형(Machado 2009, severity 1.0)에서는 쌍마다 ΔE76 ≥ 8 또는 ΔL\* ≥ 5 — 올리브·테라코타처럼 색상이 한 점으로 모이는 쌍은 명도만으로 갈리게 둔다. 위 값은 이 기준을 만족하는 **최소** 농도다(한 단계 낮추면 깨진다).
- 밴드 위 글자는 다섯 종 모두 --ink-2 다. §18 "연체 카드: 호실번호·금액 --tc" 는 표면이 중립일 때 글자가 상태를 지는 문법이고, 밴드 티어는 표면이 이미 짙은 테라코타라 같은 붉음을 글자에 또 얹으면 라이트 3.00:1 · 다크 4.04:1 로 AA 를 못 넘는다. 붉음은 표면 몫으로 한 번만 쓰고 강조는 무게로 진다(금액 700 · 연체 일정줄 600).
- 밴드 타일 hover 는 opacity 금지다. hover:opacity-75 는 표면과 글자를 함께 카드색 쪽으로 25% 섞어 색 체계 상한을 쥔다 — 그 상태로는 다섯 밴드의 최소 ΔE76 을 6.77 위로 못 올린다(전 조합 탐색). 정본은 .room-tile 의 2px --coral outline(§27 hover:border 문법의 타일판, 레이아웃 무이동).
- Do: --tc는 CTA·강조에만, --cream이 카드 배경. Don't: raw 무지개색·임의 hex·라이트 UI 순백/순흑·구코랄 rgba(244,98,58,…) (전면 금지, 2026-07-10 전수 제거) · **코랄 솔리드 채움은 CTA·연체·부유 액션에만 — 필터·선택 칩의 상태 표시에 코랄 채움 금지**(2026-08-25 정비).

  - **표: 라벨 10pt/500 · 값 10.5pt**(§26 표 기준), 금액 우측 정렬 tnum, 가로 hairline. 전년 대비 증감은 값 아래 8.5pt 회색 한 줄. 음수는 `−` + --p-tc. 0 은 `—`. **예외: 미수 증감 칸은 부호만 붙이고 무채색이다**(미수 감소는 좋은 소식이라 --p-tc 를 쓰면 경고색이 된다. 화면 deltaBadge 는 증가 warning · 감소 success). 넘치면 다음 장으로 이어진다. **행 안은 안 쪼개고 머리줄은 장마다 다시 선다.** 산정 기준은 항목 단위로 장을 넘길 수 있다(마지막 장이 주석만 남은 빈 장이 되지 않게).
  - 페이지 번호는 §26 본문 그대로 **2장 이상만**(라우트가 장수를 센 뒤 정한다). 꼬리말 틀은 계약서와 같은 공용 틀(왼쪽 `n / N` · 오른쪽 상호, 8pt, 좌우 20mm).
  - 글꼴을 못 구하면 **종이를 안 만든다**(503). 화면이 받은 바이트를 연도별로 다시 쓰므로, 네모 종이를 한 번 받으면 다시 눌러도 같은 네모가 나간다.

## §27 인터랙션 문법

- 27.1 저장: 단일 값 즉시 반영형(토글·스텝퍼·셀렉트 1개)=즉시 저장+토스트, 버튼 없음 · 폼형(2필드 이상/텍스트)=저장 버튼 상시 노출(조건부 등장 금지) · 파괴적·대량=ConfirmDialog+undo 병행. 같은 카드 안 혼용 금지. 여러 종류 행이 섞인 이력 목록의 한 건 수정은 행 [수정] RowActionBtn → width sm Modal 폼이고, 그 건의 되돌림·파괴 동작은 Modal 발끝 `관리`(§13)에 둔다. 목록 전체를 켜는 편집 모드는 두지 않는다. (2026-10-27 등재, 운영자 지적 "편집을 누르니 내역 전체를 수정할 수 있게 되버리네", 정본 `components/ui/RecordEditShell.tsx`, 감지망 `scripts/check-room-record-edit.mjs`. 방 모달 작업 이력·호실 관리 작업 탭이 같은 행을 쓰고 층만 다르다(방 모달 안 260, 페이지 200). 저장 토스트 [적용취소] 는 저장 직전 모습 전체를 서명 토큰으로 되돌리고 그사이 바뀌면 거부한다.)
- 27.2 실패: 서버·통신=토스트(화면 무반응 금지) · 검증=인라인 · 이중 통지 금지 · fire-and-forget promise는 catch 필수.
- 27.3 선택 모드: 명시 '선택' 버튼 정본, 롱프레스는 보조. 롱프레스 전용 진입 금지.
- 27.4 undo vs 확인창: 비파괴=토스트 [적용취소] · 파괴적=ConfirmDialog(danger, impact) 그리고 가능하면 undo도. 택일 아님. undo 불가는 확인창에서 고지.
- 27.5 취소는 무해: '취소'·Esc·배경 클릭은 항상 무변경. 취소에 실 동작 금지, 제3 선택지는 버튼 3개(choiceDialog).
- 27.6 검색 스코프: 현재 필터(탭·월) 안에서. 스코프 밖은 "다른 보기에 N건 ›" 안내(자동 해제 금지). 월 범위 고지는 "OO은 선택한 달 기준입니다" 단일 문형.
- 27.7 앱 밖으로 나가는 이동: 홈화면 앱(standalone)에는 주소창도 뒤로가기도 없다. target="_blank"·window.open 으로 우리 마크업이 없는 목적지(PDF 응답·외부 URL)를 열면 돌아올 길이 사라진다. 앱 안에서 이어서 할 동작은 앱 안 라우트로 보낸다. 새 창은 앱을 떠나는 것 자체가 목적일 때만 쓰고, 그 자리에 복귀 경로를 함께 둔다. 모바일에서 PDF 를 넘길 때는 새 탭이 아니라 공유 시트를 쓴다(프린트가 그 안에 있다).
- 27.8 막힘과 이유(2026-10-23 등재, 운영자 승인 '추천대로'). 운영자 원문 "이렇게 묻지 않도록 비활성화 된 이유와 풀 수 있는 방법을 간단하게 확인할 수 있는게 있으면 좋겠어". 입실 취소한 입주자를 '문의'로 돌리려는데 상태 칸의 '문의'가 투어일 때문에 비활성이었고, 이유가 코드 주석에만 있었다.
  ① **그 자리에서 풀 수 있는 막힘은 막지 않는다.** 고르게 두고, 고른 탓에 바뀐 것을 그 칸 아래 한 줄로 보이고, 되살리기 링크를 둔다(확인창 없음, 링크 문법은 '투어일이 지났습니다 · 투어 완료로 변경' 과 같다). 되살리기는 고르기 직전 모습 전체로 돌아간다. 지운 값만이 아니라 그때의 선택(상태 칸이면 직전 상태)까지 함께 쥐었다가 돌려놓는다(입실 취소에서 '문의'를 골랐다 되살리면 입실 취소다). 바뀐 것은 폼 안에만 있고 저장해야 반영된다. 취소는 §27.5 대로 무변경이다. 정본 적용은 입주자 수정 폼 상태 칸 '문의'(투어일을 비우고 `투어일(9월 28일)을 비웠습니다 · 저장하면 문의로 바뀝니다 · 투어일 되살리기`).
  ② **정말 쓸 수 없는 것만 막는다.** 행 동작은 숨기고 같은 자리에 캡션(§22 ②), 커스텀 선택지는 비활성 + 같은 줄 이유(§22 ② 옮기기 목적지), 네이티브 option 은 `라벨 (짧은 이유)` + select 아래 푸는 법 한 줄. 칸 전체가 잠기면 칸 아래 한 줄이다.
  ③ **제출 버튼이 막히면 버튼 위나 아래 한 줄로 이유를 말한다.** 이유 없이 흐린 버튼만 남기지 않는다.
  ④ **title·hover 만으로 이유를 전하지 않는다**(터치 화면에는 hover 가 없다). 버튼 이름을 title 에만 두지도 않는다. i 아이콘(InfoHint, §19)은 개념 설명용이라 지금 상태의 이유에 쓰지 않는다.
  ⑤ 문장은 `~라서 고를 수 없습니다 · ~하면 됩니다` 두 마디이고(동사는 자리에 맞게 고칠·더 고를 등), 같은 막힘을 서버도 거부하는 자리에서는 그 거부 문장과 한 벌이다. 이유를 말한 자리 옆에 같은 사실을 또 적지 않는다(입주일 상속 안내가 '509호 계약과 같은 입주일입니다'를 말하면 잠김 캡션은 푸는 법만 보탠다). 링크가 붙으면 구분점과 링크는 한 덩이로 줄바꿈된다.
  · 정본 컴포넌트 `WhyCaption`(components/ui/WhyCaption.tsx): id · 글 · 선택 링크. 10.5px `--warm-muted`, 링크 `--tc-text` 밑줄, 링크 히트 44px(음수 여백으로 줄 높이 안에 접는다). 놓이는 면 규칙(2026-10-26 개정): 불투명 면(`--canvas`·`--cream`·`--cream-soft`·`--cream-3`)은 보조 잉크 하한(§03, 감지망 `check-seg-ink-off` ⓖ)이 4.5:1 을 보장하므로 어느 면이든 둔다. 반투명 틴트 면(`bg-[var(--x)]/NN`·`-bg` 토큰·rgba)은 겹친 결과가 달라 실측해 `check-why-caption` ⓓ 의 표에 라이트·다크 수치를 적는다(표에 없으면 붉다). 실측 `--cream` 라이트 6.45:1 · 다크 4.97:1, `--canvas` 5.18:1 · 5.69:1, 단기 요금 박스(`--cream` 위 `--canvas/50`) 5.81:1 · 5.37:1, 링크 6.14:1 · 4.63:1. 반 칸(2열 격자의 한 칸)에 두면 320px 에서 다섯 줄까지 접히므로 격자 밑 전폭(col-span-2)에 둔다. 막힌 컨트롤은 그 id 를 `aria-describedby` 로 가리킨다. `Btn`·`RowActionBtn` 은 `reason`(캡션 id) 프롭을 받으면 네이티브 disabled 대신 `aria-disabled` 로 막아 포커스가 닿고 `aria-describedby` 를 스스로 단다. 막힌 Btn 은 hover·active 피드백을 걷는다. `DatePicker` 는 `describedBy`. 1차 적용은 상태 칸 '문의', 단기 요금 박스 입주일 잠김, 희망 호실 5개 상한, 현금영수증 켜기 줄 '발행 기록', 배치도 적용취소·다시 적용(↩↪ 글자와 title 을 글자 라벨로). 감지망 `scripts/check-why-caption.mjs`. 나머지 비활성 자리 전수 감사는 2차다.
- 27.9 기준값과 그 값을 쓰던 기록(2026-10-27 등재, 운영자 승인 '추천대로', 홍은주 602호 사건). 폼의 자동 채움은 새 기록과 빈 칸에만 한다. 저장된 값은 다른 칸을 바꿔도 덮지 않고 칸 아래 WhyCaption 한 줄로 기준값을 알리며 한 번 눌러 바꾸고 되살린다(`418호 150,000원 그대로입니다 · 602호 기준 30,000원으로 바꾸기`). 기준값(방 이용료)을 고치면 옛 기준값 그대로 쓰던 기록은 묻지 않고 따라가고(토스트 [적용취소]), 기준값과 다른 기록(협의가)은 저장할 때 이름·금액을 적은 choiceDialog `[계약에 적용] / [호실만 저장] / [취소]`(기본 포커스 취소)로 묻는다. 이미 청구된 달은 그대로다. 정본 `lib/leaseRentAutofill`·`lib/roomRentSync`, 감지망 `scripts/check-lease-rent-autofill.mjs`·`scripts/check-room-rent-sync.mjs`.
- 27.10 서명 패드 상태 줄(2026-10-26 등재, 운영자 승인, 신고 c6eb427d 어르신 서명 인식). 손글씨 서명 패드 바로 아래 한 줄이 지금 무엇을 받고 있는지 말한다. 네 상태는 대기 `손가락 끝으로 성함을 써 주세요`(--ink-s) · 긋는 중 `서명 받는 중…`(--ink) · 받음 `서명 받음 · 확인을 누르세요`(--success-fg 600) · 짧음 `조금 더 길게 써 주세요`(--warning-fg 600, 거절 전 예고)이고 판정은 확인 버튼과 같은 정본 `lib/signatureInk`(총 획 길이 60px 바닥, 낮추지 않는다)다. 12px, 줄 수만큼 높이를 미리 잡아 상태가 바뀌어도 버튼이 안 뛴다. 원격 서명은 사전 병기(`lib/signGuideText` 8개 언어 `pad.st*`), 운영자 화면은 한국어. 오류가 서면 오류 상자가 그 자리를 대신한다(같은 말을 두 번 안 한다). 확인 버튼은 disabled 가 아니라 받음 전 회색(`.remote-submit-wait` 문법, opacity 없음), 받음 뒤 코랄이다. 패드가 열린 동안 오버레이·모달 전체가 `touch-action: none` 이고 잉크가 있으면 배경 누름을 무시한다(§12). 감지망 `scripts/check-sign-pad-input.mjs`, 진리표 `scripts/test-sign-pad-trace.ts`.

## §30 키보드 · 보이는 띠

키보드 패널 결정(2026-09-02, 운영자 승인). 소프트 키보드가 선 동안 화면의 진실은 '보이는 띠'(키보드 위에 남은 시각 뷰포트)다. 판정과 기하는 코드 정본 한 벌에서만 나온다.

- 판정 정본은 `lib/keyboardViewport.ts` 다(순수 함수 · 스냅샷 회귀가 고정).
  - 기준틀 = 화면 고정 상자(fixed inset-0)의 높이 H 와 client 위 끝 T0 (2026-10-20 개정, 신고 be5316e8). 재는 곳은 `lib/viewportFrame.ts` readKbdSnapshot 한 곳이고, 키보드 기하 경로의 다른 파일은 window.innerHeight 를 읽지 않는다. 키보드가 선 iOS 는 팬하면 innerHeight 를 812 − offsetTop 이나 vv.height 로 줄여 보고하지만 고정 상자는 높이를 지킨다. 안드로이드·데스크톱은 H = innerHeight, T0 = 0 이라 종전과 같다.
  - 열림 = H − vv.height > 60px. 외장 키보드 단축바(약 55px)는 열림이 아니다.
  - 겹침(셸 --kbd-inset · 오버레이 아래 인셋) = H − offsetTop − vv.height. 오버레이 위 인셋 = offsetTop. 재노출 띠 = client 기준 T0 + offsetTop 부터 vv.height 만큼.
  - 키보드가 선 동안(표식 + 키보드 칸 포커스 + 기준틀 열림)의 window resize 는 팬이다. 판정만 갱신하고 --kbd-inset 재기록·재노출·복원(scrollTo)은 하지 않는다. '크기는 vv resize 에서만'(716e7b0c) 규칙이 window 쪽 문으로 새지 않게 한 것이다. 두 프레임 뒤 한 번 더 보고 닫힘이면 그때만 재동기한다(키보드가 내려가는 순간 옛 vv 로 팬 판정되는 경우).
  - --kbd-inset 은 셸 스크롤 여유(패딩)용이다. fixed 요소의 위치로 쓰지 않는다. 위치는 useVisibleBand 의 --vv-bottom(팬마다 갱신)을 쓴다.
  - 줌 게이트: vv.scale > 1.02 면 키보드 대응 전체 중립(핀치 줌을 키보드로 오판해 유령 패딩·팬 강제 복원이 서던 자리).
  - 겹침 인셋 상한: 띠의 70%를 넘으면 클램프(기각이 아니라 클램프 — 가로 모드의 정당한 큰 겹침을 버리지 않는다).
  - 복원은 진짜 닫힘(잔차 2px 이내)일 때만. 열린 채 OS 가 만든 팬을 되감지 않는다.
- 재노출 목표선 = 보이는 띠의 위에서 35%. 중앙(50%)이 아니다 — 다음 칸 미리보기가 죽는다. 목표선 위에 있던 칸은 위 여백 16px 만 보정.
- 소유자 구조. 겹침 변수 --kbd-inset 과 html[data-kbd-open] 스탬프는 ViewportOffsetGuard 가 단일 소유자다(문서 흐름·셸 몫). 오버레이의 띠 인셋(--vv-top/--vv-bottom)과 띠 높이(--vv-h)는 useVisibleBand 훅이 단일 소유자다(Modal 은 종전 변수명 --modal-vv-*·--modal-vvh 로 같은 훅을 쓴다). 다른 자리에서 visualViewport 를 직접 구독하지 않는다.
- 오버레이 규칙: fixed inset-0 오버레이(확인창·시트·검색·수제 다이얼로그)는 공용 Modal 을 쓰거나 useVisibleBand 로 인셋 두 항 + 패널 상한을 받아야 한다. --kbd-inset 하단 한 항만 미는 방식 금지(위 겹침과 시트 높이를 모른다). 감지망 check-kbd-canonical.mjs 가 지킨다.
- 셸: (app) 셸과 admin 셸 둘 다 ViewportOffsetGuard 를 마운트한다. admin 본문 여유는 자체 padding(--kbd-inset)이고 .app-main 재사용 금지.
- 뷰포트 메타: interactiveWidget 'resizes-content' (Android 동작 고정).
- 명시적 비대응(패널 합의): iPad 플로팅·분할 키보드, PeekSheet iframe 내부의 재노출(바깥 시트 기하만 보정), 외장 단축바 아래 최하단 24px.
