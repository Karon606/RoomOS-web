> **이 문서는 Claude Design용 프롬프트다.** 아래 "프롬프트" 절을 그대로 전달하면 작업할 수 있도록 작성됨.

## 프롬프트 (Claude Design에게)

스테이음(stayeum) 고시원/원룸텔 운영 앱의 **재고관리** 화면을 재설계해줘. 목표는 **두 탭(소모품·부식 / 비품·자재)의 UI/UX 언어를 하나로 통일**하는 것. **모든 기능은 그대로 유지**하되, 점점 복잡해진 화면을 정돈하고 두 탭이 같은 디자인 언어를 쓰게 만들어줘.

### 산출물
1. **HTML 목업** — 기존 브랜드 가이드 HTML들과 **동일한 토큰·컴포넌트·스타일**을 써서, 다음 상태를 모두 보여줄 것:
   - 탭 A: 소모품·부식 — 기본 보기 / 선택 모드 / 카드 상세(점검·병합) / 빈 상태 / 로딩 스켈레톤
   - 탭 B: 비품·자재 — 기본 보기 / 선택 모드 / 합치기 / 빈 상태
   - 공통 패턴(페이지 셸·헤더·카드·하단 액션 알약·모달·뱃지)을 **한 벌의 컴포넌트**로 정의
2. **간단한 근거 노트** — 무엇을 통일했고 왜인지, 기존 대비 무엇이 줄었는지.
3. **사용 토큰·컴포넌트 목록** — 새로 만든 게 있으면 가이드에 편입할 수 있게 명시.

### 반드시 지킬 것 (가드레일)
- **데이터 모델·기능 삭제 금지.** 아래 "보존할 기능 목록"의 모든 동작이 새 디자인에서도 가능해야 함.
- **기존 디자인 토큰·컴포넌트 재사용** (별도 파일 참조). 새 컴포넌트는 최소화하고, 만들면 가이드 스타일을 따를 것.
- **모바일 우선**, 한국어 UI, 따뜻한 크림/테라코타 팔레트.
- 두 탭이 **같은**: 페이지 헤더 구조, 카드 해부구조, 선택 모드 하단 알약, 병합/합치기 인터랙션, 적용취소(undo) 노출 위치, 빈/로딩 상태.

## 현재 상태 (디자이너가 알아야 할 사실)

두 탭은 **데이터 성격이 근본적으로 다르다** — 그래서 화면이 갈라졌고, 통일의 핵심 난점이다:
- **소모품·부식** = 재고 *수량 추적*(현재고·점검·소진예측·드래프트). "지금 몇 개 남았나".
- **비품·자재** = 내구재 *배치 관리*(어느 방/공용부에 있나·미배정 여분). "어디에 있나".

### 탭 A — 소모품·부식 (`InventoryClient.tsx`) 보존할 기능
- 헤더 액션: **병합 적용취소·규칙**, **카테고리 설정**, 품목 추가, 지출에서 자동 등록, 점검 진입(품목별/위치별), 전체 재고 보정, 제외 품목, 위치(저장소) 설정
- **카테고리별 섹션**(색 점 + 별칭) 그룹핑
- 수령 대기 섹션(인라인 '수령 완료')
- 카드: 현재고 수량, '점검 중' 뱃지, 'N건 수령대기' 뱃지, 점검/유지 버튼, 상세 모달 진입
- **선택 모드 → '위치 일괄 할당'**(단일 액션 하단 알약)
- **상세 모달**: 점검 이력, 라벨 편집, **'다른 카드와 병합'(MergeSection: 대상 드롭다운+방향 확인 모달)**
- 모달들: 품목추가/카테고리설정/병합결정(OCR후)/병합규칙·적용취소/전체보정/위치설정/제외품목/일괄위치/상세

### 탭 B — 비품·자재 (`AssetsClient.tsx`) 보존할 기능
- 헤더 액션: **선택**(만 있음)
- **배정 위치별 섹션**: 수령 대기 / 미배정(여분) / 공용 자재 / 방별 / 공용부별
- 카드: 품목·규격·수량, 금액, 합산 펼치기(구매 N건), 액션: 수령완료↔수령대기로, 공용 자재로↔해제, 배정/배정 변경, **합치기**
- **선택 모드 → 하단 알약: '방·공용부 일괄 배정' + '합치기'(대표 골라 통일)**
- **합치기**(병합): 카드별 '합치기'(같은 구역·분류 대상 드롭다운) + 선택모드 합치기. **적용취소는 환경설정 '품명 병합'**

### 통일이 필요한 구체적 불일치 (이게 핵심 과제)
1. **그룹핑 축이 다름** — A=카테고리(색 점), B=배정 위치. → 공통 섹션 헤더 패턴 + 각 탭의 축은 유지하되 *시각 언어*는 통일.
2. **헤더 액션 밀도가 다름** — A=버튼 6+개로 과밀, B=선택 1개. → 공통 헤더 패턴(예: 주요 1~2개 노출 + 나머지 '⋯ 더보기/설정' 묶기) 제안.
3. **병합/합치기 패러다임·적용취소 위치가 다름** — A=상세모달 속 MergeSection + 전용 '병합 규칙' 모달, B=인라인 합치기 + 환경설정 undo. → **하나의 '합치기' 인터랙션 + 하나의 적용취소 위치**로 통일.
4. **선택 모드 하단 알약 액션이 다름** — A=일괄 할당만, B=배정+합치기. → 공통 알약 패턴(탭별로 가능한 액션만 노출).
5. **카드 해부구조가 다름** — 수량/뱃지(A) vs 금액/배정상태(B). → 공통 카드 템플릿(좌: 제목·메타, 우: 핵심 수치 1개, 하단: 액션 행, 옵션: 펼치기/뱃지)로 흡수.
6. **상세 진입 차이** — A=리치 상세 모달, B=인라인 펼치기만. → 상세 진입 방식 통일 여부 제안.

### 톤/원칙
- 사용자(운영자)의 반복 피드백: "두 탭이 따로 논다", "점점 복잡해진다". → **덜어내고 일관되게**가 최우선. 화려함보다 정돈.
- 모든 적용 기능엔 **적용취소(undo)** 가 있어야 한다(앱 원칙). 새 디자인에서도 undo 노출을 명확히.
