# 디자인 브리프 — 리스트·테이블 화면 통일 (호실관리·수납관리·고객관리)

> **이 문서는 Claude Design용 프롬프트다.** 아래 "프롬프트" 절을 그대로 전달하면 작업할 수 있다.
> 배경: 재고관리는 §21로 통일 완료. 이제 호실·수납·고객 3개 리스트/테이블 페이지가 제각각이라 통일이 필요한데,
> 브랜드 가이드는 **컴포넌트 어휘는 충분**하지만 **화면 레벨 IA(카드 필드 우선순위·리스트 페이지 복합 레이아웃·sticky 테이블)는 미정의** —
> §21이 재고에 그랬듯 이 3페이지엔 **§22가 필요**하다. (Claude Code 감사 결과, 2026-06-24)

---

## 프롬프트 (Claude Design에게)

스테이음(고시원/원룸텔 운영 앱)의 **리스트·테이블 화면 3종**을 하나의 디자인 언어로 통일하는 **브랜드 가이드 §22**를 만들어줘.
대상: **호실 관리(`/room-manage`)·수납 관리(`/rooms`)·고객 관리(`/tenants`)**. 이미 통일된 **재고관리(§21)** 와도 시각 언어가 이어져야 함.
**모든 기능은 그대로 유지**하되, 점점 제각각이 된 세 화면을 같은 골격·패턴으로 정리하고 **사용자 편의성**을 끌어올리는 게 목표.

### 산출물
1. **`docs/brand-guide-v1.3.md`에 붙일 `§22 리스트·테이블 화면` 절** (마크다운, §21과 동일 형식) — 아래 6개 정본 포함:
   - **22.1 ListPageShell** — 리스트 페이지 전체 골격·섹션 순서·간격: 헤더(제목+주요 1~2 CTA) → 검색 → 빠른필터 → 정렬/표시항목 → 본문(카드/테이블) → 빈/로딩. 모바일·데스크탑 모두.
   - **22.2 카드 필드 우선순위 정본** — 도메인별(호실/수납/고객) 카드 1·2·3순위(식별자→상태→금액→옵션)와 **식별자 스타일 통일**(현재 호실번호가 base vs coral bold로 제각각). RoomCard 위에 얹는 규칙.
   - **22.3 빠른필터 패턴** — 칩(toggle·다중) vs SegmentedControl(radio·단일) 사용 기준 통일(현재 호실=칩, 수납·고객=Segment 혼용).
   - **22.4 sticky 테이블 정본** — 데스크탑 표의 좌측 고정 열(호실+입주자명) 개수·z-index·배경·상태색 좌측보더(3px) 규칙.
   - **22.5 배치 선택 모드** — 선택 진입 → 체크박스(22×22·radius 7·✓·색 토큰) → 하단 다크 알약(재고 SelectionPillBar 재사용) → 배치 액션. 수납은 현재 선택모드 없음 — 추가 여부 제안.
   - **22.6 모달 vs 전역 셸 결정 규칙** — 호실·고객은 페이지 내 폼 모달, 수납은 전역 Prism 셸(EntityModal). 언제 어느 쪽인지 표준화.
2. **HTML 목업** — 기존 가이드 HTML과 동일 토큰·컴포넌트로, 3페이지 × (모바일 카드 / 데스크탑 테이블 / 선택모드 / 빈상태) 상태.
3. **근거 노트** + **사용 토큰·컴포넌트 목록**.

### 반드시 지킬 것 (가드레일)
- **데이터·기능 삭제 금지.** 아래 "현재 구조"의 모든 동작이 새 디자인에서도 가능해야 함.
- **기존 토큰·컴포넌트 재사용** — 새 색(hue) 추가 금지(§14.4 무지개 디톡스). 새 컴포넌트는 최소화.
- **모바일 우선**, 한국어, 따뜻한 크림/테라코타.
- 재고(§21)와 **이질감 없게** — SelectionPillBar·StatusBadge·Modal·Btn·SegmentedControl·MoneyDisplay 등 공용 그대로.
- §17(반응형 표↔카드 768px), §14.4(의미색), §09/§10/§11(확인·적용취소·토스트), §13(폼), §16(빈·로딩) 정본 준수.

## 현재 구조 (감사 요약 — 디자이너 참고)

### 호실 관리 (`/room-manage`, RoomManageClient)
헤더(선택·등록 2 CTA) + 통계 부제 + 검색(SVG 아이콘) + **상태 빠른필터 칩**(공실·예약·거주중·퇴실예정, toggle) + 9항목 고급필터 패널(grid-2) + SortSelect + DisplayFieldsMenu. 본문=**호실 카드 그리드**(RoomCard kind=resident/vacant, 우측 썸네일). 선택모드→하단 배치바→BatchEditRoomsModal. 자체 모달(호실 추가/수정, 사진 grid). EmptyState 사용.

### 수납 관리 (`/rooms`, RoomsClient)
헤더(제목 + **MonthSelector**) + 검색(🔍 이모지) + **SegmentedControl 빠른필터**(전체·미납·퇴실예정·납부예정·완납·임시조정) + 층 select + 표시항목 2종. 본문=**모바일 카드 / 데스크탑 sticky 테이블**(§17). 카드: 호실번호(coral bold)·입주자·금액(잔액/선납/미수 sub). 공실 별도 섹션. **선택모드 없음.** 모달 없음(전역 EntityModal=Prism 셸 PaymentBody). 빈상태=텍스트만.

### 고객 관리 (`/tenants`, TenantClient)
헤더(선택·등록 2 CTA) + **탭 SegmentedControl**(입주자·문의/예약·입실취소·퇴실, 인원수) + 탭별 필터 Segment + 층 select + 검색 + colVis(13열)/cardFields. 본문=**모바일 카드 / 데스크탑 sticky 테이블**. StatusChip(정상=텍스트, 예외=배지). 선택모드→배치바→배치편집. 자체 모달(추가/수정[계약·수납·서류 탭]/배치/보증금환불/가격변동).

### 핵심 불일치 (통일 과제)
1. **카드 식별자 스타일**: 호실번호가 base(호실) vs coral bold(수납) — 통일 필요
2. **빠른필터**: 칩(호실) vs Segment(수납·고객) — 기준 통일
3. **상태 뱃지 sub**: 수납·고객은 "D-13·3일 초과" sub 사용, 호실은 미사용 — 호실에도 일정 sub
4. **검색 아이콘**: SVG(호실) vs 이모지🔍(수납) — 통일
5. **선택모드**: 호실·고객 有 / 수납 無 — 일관성 결정
6. **빈/로딩**: 호실만 EmptyState, 나머지 텍스트/없음 + 스켈레톤 전무 — §16 통일
7. **모달 아키텍처**: 자체 모달(호실·고객) vs 전역 셸(수납) — 표준 결정

### 가이드로 이미 충분(=Code가 바로 적용 가능, 디자인 갭 아님)
색·의미 토큰(§14.4), StatusBadge 병렬패턴(§14.3), ConfirmDialog(§09), pushToast(§11), 폼 입력(§13), 반응형 표↔카드(§17), EmptyState(§16). → §22가 "어떻게 배치/우선순위" 만 정해주면 나머지는 기존 컴포넌트로 구현 가능.
